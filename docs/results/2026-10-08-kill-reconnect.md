# 정원 규모에서 백엔드를 죽였다 살리기 (T116)

2026-10-08. 질문은 둘이었다.

1. **1,000테이블 · 9,000명이 붙은 백엔드를 죽였다 살리면 1코어가 5분 안에 다시 받나.**
   T113은 서버가 사는 채 회선이 흔들린 경우였다.
2. **다시 붙은 뒤 판이 다시 도나.** 6테이블 kill에서 소켓은 돌아오는데 핸드가 0이었다.

## 무대

[`2026-10-07-load-ceiling.md`](./2026-10-07-load-ceiling.md)와 같다(1코어 · 512MB ·
bcrypt 4 · 라이브 생각 시간). 램프 A(6테이블마다 대회 하나, 170대회). 착석에만 6코어를
빌리고 2코어 → 1코어로 내린 뒤, 시작 20분에 `docker kill` → 8초 뒤 `docker start`
(1코어 유지). 부팅 3초.

## 판이 안 돌던 것은 봇이었다

재기동하면 진행 중이던 대회는 `SYNCING`이 되고 핸드 도중이던 테이블에는
`resumePending`이 선다. 딜러가 전부 돌아오면 띠가 걷히고, 판을 여는 것은 테이블마다
딜러의 재개(`RESUME_TABLE`)다. 봇 딜러는 재개를 몰랐고 `tournamentSyncing`도 안 들었다 —
띠가 걷힐 때 서버는 `renderGame`을 다시 보내지 않으므로 다음 판단의 계기가 없었다.

봇 딜러가 띠가 걷히면 다시 판단하고, `resumePending`이면 5초 뒤 재개를 누르게 했다.
6테이블 kill에서 kill 뒤 핸드 0 → 12, 멈춘 4테이블 4/4 재개.

## 연결 복구 — 합격

kill 뒤 다시 열린 소켓 10,351. **좌석이 남은 사람의 소켓은 전부 5분 안에 붙었다.**
300초 뒤의 세션 195개는 정확히 300초 뒤의 1008 거절 195건이다 — 아래 탈락자의
태블릿이 「이 테이블의 좌석이 없습니다」로 거절당하며 도는 재시도다.

| | 표본 | 중앙 | p90 | p99 | 최대 |
|---|---|---|---|---|---|
| 테이블 전체 | 719 | 76초 | 92초 | 157초 | 170초 |
| 좌석 | 719 | 76초 | 92초 | 157초 | 170초 |
| 딜러 | 784 | 45초 | 54초 | 56초 | 98초 |
| 대회 `SYNCING` 종료 | 167 / 167 | 57초 | 60초 | — | 102초 |

- 테이블 표본이 1,000이 아닌 이유: 하네스가 1006으로 닫힌 것만 폭발로 셌는데 216테이블은
  코드 없이 닫혔다(고쳤다, `406a4e6`). 65테이블은 완료가 없다 — 탈락으로 좌석이 사라진
  테이블로 본다(테이블별 대조는 로그에 table id가 없어 못 했다).
- 티켓 무응답 3,635건(부팅 중 연결 거부), 최대 대기 159초. 포기 5건은 kill 6~9분 뒤로,
  탈락자 태블릿이 8회를 다 쓴 것이다. 대회 170 중 3은 램프가 안 쓴 대회(`PENDING`)다.
- 핸드: kill 전 20분 3,163 → kill 뒤 10분 2,758.

## 그러나 장애가 111명을 탈락시켰다 — T117

탈락 111명은 **전부 재기동 뒤 「리바인 응답 시간초과」**다 — kill 전 20분에는 시간초과가
0건이다(실행 전체 리바인 수락 8,944). 시간초과는 03:05:42~03:06:12, 첫 `SYNCING` 종료(03:05:26) 1초 뒤부터
열린 15초 창들이다.

1. 서버가 내려가 있는 동안 좌석의 첫 티켓이 실패해 대기 폭이 ×2 · ×4로 벌어진다
2. **딜러 오프셋은 40초 고정이라 딜러가 좌석보다 먼저 돌아온다** — 딜러 중앙 45초 ·
   좌석 중앙 76초. `reconnect-policy.ts`의 「딜러는 좌석 뒤」가 서버 다운에서 뒤집힌다
3. `SYNCING`은 **딜러만** 센다. 딜러가 다 오면 띠가 걷히고 쇼다운이던 테이블에서
   승자를 넣는다
4. 파산자의 리바인 프롬프트가 아직 끊긴 태블릿으로 가고, 15초 뒤 거절로 세어 탈락한다

딜러 화면에는 딜러 n/n만 있고 좌석 접속 여부가 없어, 재개나 승자 입력을 미룰 근거가
화면에 없다. 봇 딜러를 「좌석이 다 올 때까지 기다리게」 고치지 않았다 — 제품 문제를
가린다.
