# 표준 무대 첫 실측 — 1,000테이블 kill · WSOP급 대회 회선 끊김

2026-10-13. 측정마다 무대가 667 · 1,000 · 200테이블로 갈려 결과끼리 비교가 안 됐다.
무대를 하나로 고정하고(`npm run load:standard`, [`load/README.md`](../../load/README.md)의
「표준 무대」) 처음 돌렸다. T118~T122를 고친 뒤 1,000테이블 kill을 잰 것도 처음이다.

## 무대

| | 값 |
|---|---|
| 전체 | 1,000테이블 · 9,000명 · 기기 10,000대 |
| 끊는 대회 | 556테이블 · 5,004명 (WSOP급 하나) |
| 대조군 | 444테이블 = 6테이블 × 74대회 |
| 서버 | 1코어 · 512MB · bcrypt 4 (착석에만 6코어, 초당 8명) |
| 순서 | 1코어 150초 → kill · 8초 뒤 start → 대회 75개 해제 → 20초 끊김 → 90초 끊김 |
| 코드 | `main` `441a2b4`와 같은 백엔드 |

한 번 앉힌 무대에서 셋을 이어 쟀다. 재접속은 좌석 토큰으로 티켓만 받으므로 착석의 bcrypt와
무관하다.

## 1. 서버 kill — 합격

| | 값 |
|---|---|
| 대회 75개 `SYNCING` 해제 (kill 뒤) | 최소 47초 · 중앙 52초 · **최대 53초** (합격선 300초) |
| 가장 큰 대회(556테이블)의 해제 | 53초 |
| 좌석 9,000대 복귀 | 중앙 32초 · p90 40초 · 최대 52초 |
| 딜러 1,000대 복귀 | 중앙 47초 · p90 51초 · 최대 52초 |
| 시간 초과 폴드 (kill → 해제 / 해제 뒤 120초) | 0 / 0 |
| 리바인 시간 초과 · 미룸 | 0 · 0 |
| 끝난 뒤 참가자 | PLAYING 9,000 |
| 1코어 이벤트 루프 p99 최대 · CPU 최대 | 300ms · 101% |

해제는 「서버가 뜨는 시각 + 기기의 첫 재시도」다. 마지막 기기가 52초에 오고 그 1초 뒤에
풀렸다. 앞선 값과 무대가 다르다 — 대회 하나 1,000테이블은 T117에서 376초(수정 전),
667테이블은 T122 뒤 85초였다.

## 2. 556테이블 대회 회선 끊김 — 폴드 거의 0

| | 20초 | 90초 |
|---|---|---|
| 서버가 알고 대회를 멈춘 시각 | 5.6초 | 4.8초 |
| 시간 초과 폴드 (알기 전 / 안 뒤 / 이은 뒤) | 1 / 0 / 0 (칩 800) | 0 / 0 / 0 |
| 리바인 시간 초과 탈락 | 0 | 0 |
| 마지막 좌석 · 딜러 복귀 (이은 뒤) | 42초 · 52초 | 42초 · 55초 |
| 딜러 재개 (마지막, 테이블 수) | 68초 · 107 | 71초 · 86 |
| 첫 핸드 (이은 뒤) | 66초 | 69초 |
| 대조군 폴드 · 끊긴 소켓 | 0 · 0 | 0 · 0 |

20초 끊김의 폴드 하나는 서버가 알기 전(5.6초 안)에 난 것이다 — 200테이블에서는 0이었다.

## 새로 보인 것 — 한 대회가 돌아오는 순간 다른 대회가 느려진다 (T130)

200테이블 측정에서는 1코어 p99가 최대 80ms였다. 556테이블에서는 대조군의 핸드 진행이
3분의 1로 줄었다. 지연이 튄 자리는 끊긴 동안이 아니라 **이은 뒤 44~50초**다. 딜러 복귀 폭
(40~50초)과 겹치지만, 재집계 · 재개 · 딜러 화면 전송 중 무엇이 채우는지는 아직 안 갈랐다.

| 이은 뒤 | 20초 끊김 lag p99 · CPU | 90초 끊김 lag p99 · CPU |
|---|---|---|
| 44~45초 | 121ms · 80% | 498ms · 89% |
| 49~50초 | 487ms · 99% | 389ms · 99% |
| 64~65초 | 82ms · 84% | 179ms · 79% |

폴드 · 탈락은 없었다. 대조군 대회의 딜러가 「승자 입력이 늦다」를 겪는 정도다.
