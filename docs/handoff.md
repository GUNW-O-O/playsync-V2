## 1. 어디까지 왔나

### 1-1. 촬영 하나가 결함 셋을 낳았다

T84는 「마무리 화면을 증명하는 촬영」인데, 그 촬영이 **제품의 구멍 둘을
드러냈다.** 둘 다 같은 모양이다 — **서버는 알고 있는데 단말에 안 알려준다.**

| 티켓 | 무엇 | PR |
|---|---|---|
| T85 | 대회가 닫혀도 단말이 모른다 | **#97** (머지됨) |
| T86 | 리바인을 기다리는 동안 테이블 전원이 모른다 | **#98** (머지됨) |

둘 다 촬영을 찍다가 「이 화면에 왜 아무 설명이 없지」에서 나왔다. 촬영이
회귀 테스트가 아니라 **검수 도구**로 값을 한 자리다.

### 1-2. 이 브랜치의 커밋

`docs/`를 뺀 전부가 촬영·자르기다.

| 커밋 | 무엇 |
|---|---|
| `753d6cf` | 층이 하나인 판에서 등수를 한 번만 찍는다 |
| `7b2bc0c` | 마무리 두 문을 좌우가 아니라 **앞뒤**로 놓는다(`parts`) |

### 1-3. 판정이 다섯에서 여섯으로

「눈으로 훑지 않는다」가 §4의 첫 줄인데 **정지 구간이 눈으로 볼 것으로 남아
있었다.** 그것을 재는 것을 더했고, 그 여섯째가 실제로 결함을 잡았다 —
`20-abort`가 20초 중 6.3초를 같은 그림으로 서 있었다.

## 2. 지금 할 것 — 재촬영

```bash
cd backend && docker compose up -d      # 내려가 있으면
npm run build -w frontend               # 프론트 소스가 바뀌었으면
node scripts/demo-settlement.mjs --only=complete --no-build
node scripts/demo-settlement.mjs --only=chop --no-build
node scripts/demo-settlement.mjs --only=abort --no-build
npm run assets:settlement
```

**하나씩 돌린다.** 셋을 한 명령으로 이으면 `next start`가 `3221226505`로
죽는다(§6). 하나씩 돌려도 두 번째 실행에서 죽을 때가 있고, 그때는 그냥
다시 돌리면 된다 — 실측으로 재시도 한 번에 통과했다.

**파이프를 걸지 마라.** `| tail`로 받으면 진행 로그가 버퍼에 묶인다.
`[판]` 줄을 실시간으로 봐야 결정성을 바로 안다.

## 3. 실측값

**재촬영이 이 값을 갱신한다.**

### 3-1. 시간

세 실행 각각 6.4~6.9분, 합쳐 **20분 남짓**. `끝` 마크는 379~389초다.

마감 대기는 30초대이고 셋 합쳐 20분이다. SSOT 커밋에서 고친다.

## 4. 무엇을 보고 판정하나

**눈으로 훑지 않는다.** 0.15초짜리는 프레임 샘플에 안 걸리고, 정지 구간은
스틸 몇 장으로는 **아예 안 보인다**. 아래를 계산으로 재고, 그 다음에 그림을
본다.

### 4-1. 자동으로 재는 것 여섯

| 무엇 | 어떻게 | 통과 기준 |
|---|---|---|
| **결정성** | 촬영 로그의 `[판]` 줄을 세 실행 비교 | 판별 승자와 남은 셋이 전부 같다 |
| **대기** | 로그의 `리바인 응답 시간초과` 건수 | **0건.** 한 건이 15초다 |
| **슬레이트 누출** | 각 면의 `slateAtMs + 0.6`이 그 면이 쓰이는 창의 **시작보다 앞**인지 | 0건 |
| **자홍색** | 창 구간의 `VMAX ≥ 240` | 0건. `20-abort`의 221은 빨간 「중단」 버튼이다 |
| **정지** | 창 구간의 `freezedetect` | §4-4 |
| **크기** | 움짤 넷 | 2MB 이하 |

앞의 넷은 촬영 로그와 `timeline.json`으로 재고, 뒤의 둘은 원본 webm을 창만큼
잘라 잰다. **최종 webp는 ffmpeg가 못 읽는다**(ANIM 청크 미지원).

```bash
# 자홍색
ffmpeg -ss <창시작-면오프셋> -t <창길이> -i <면>.webm \
  -vf 'signalstats,metadata=print:key=lavfi.signalstats.VMAX:file=-' -f null -

# 정지
ffmpeg -ss <창시작-면오프셋> -t <창길이> -i <면>.webm \
  -vf 'freezedetect=n=-70dB:d=2' -f null -
```

**「면오프셋」은 계산하지 말고 영상에서 읽는다.** 슬레이트(자홍색 0.15초)가
찍힌 프레임을 찾아 `slateAtMs`에서 빼는 것이 유일하게 맞는 방법이다 —
`make-demo-assets.mjs`의 `probeSlate`가 그것이고, 계산으로 맞추려던 두 번이
다 틀렸다(그 파일 머리말).

### 4-2. 움짤 넷 — 무엇을 주장하고 어디가 깨지면 무슨 뜻인가

#### `11-entry-not-player` · `complete` · 딜러 T1·T2 + 리바인 좌석 + 전광판

한 판에 스물이 사라지고, 이어서 한 사람이 리바인을 눌러 **엔트리만** 36이
된다.

| 봐야 할 것 | 틀리면 |
|---|---|
| 딜러 타일 **둘 다** 승자 결정 모달이 뜨는가 | 한쪽이 소켓 조작으로 돌아갔다. 펠트가 저절로 바뀌는 그림이면 인과가 반만 읽힌다 |
| 좌석 타일에 **리바인 팝업과 누르는 손** | 그 팝업은 본인에게만 간다(`sendToTableUser`). 없으면 「누가 눌렀나」가 화면에서 사라진다 |
| 리바인 대기 중 딜러 타일에 「N번 자리의 리바인을 기다립니다」 | T86 회귀 |
| 그 구간 딜러 배지가 **「핸드 종료」** | T86이 함께 실어 보내는 전이다. 「쇼다운」이면 안 나간 것 |
| 전광판 엔트리 35 → 36인데 **참가 인원은 35 그대로** | 둘이 같이 움직이면 분모가 사람 수라는 뜻. `itm-scaling` 회귀 |
| 상금 목록 다섯 줄 → 여섯 줄 | 리바인이 경계(36)를 못 넘겼다 |
| 테이블들이 **같은 순간에** 도는가 | 하나가 앞 절반을 멈춰 있으면 순차로 돌아간 것 |

#### `03-four-tables-to-one` · `complete` · 좌석 둘 + 콘솔 + 폰 둘

상점이 좌석을 풀고, 사람이 폰에서 참가 OTP를 보고, 그 번호를 새 자리
태블릿에 넣는다.

| 봐야 할 것 | 틀리면 |
|---|---|
| **콘솔이 창 처음부터 16 · 36 · 1,620,000** | `reload`가 마크 뒤로 갔다 |
| **콘솔 조작이 폰보다 먼저** | 폰이 먼저 열리면 「상점이 풀어서 사람이 본다」의 인과가 뒤집힌다 |
| 폰에 **OTP 여덟 자리가 떠 있는가** | `revealOtp` 실패. 이 프레임의 주장이 사라진다 |
| 옮겨 앉은 뒤 **스택이 그대로** | 줄면 칩이 좌석에 묶인 것. T29 회귀 |
| 좌석 해제가 **두 단계**로 | 탭 → 자리 토글 → 「고른 자리 해제」가 화면의 설계다 |
| 커서가 OTP 숫자를 안 가리는가 | 여덟 자리 중 하나가 덮이면 번호를 대조할 수 없다 |
| **착석 둘이 겹쳐서** 일어나는가 | 한 사람씩 끝나면 같은 조작의 반복이지 「합쳐지는 중」이 아니다 |

#### `05-two-doors-same-ledger` · 조각 둘 (`chop` → `complete`)

**좌우가 아니라 앞뒤다.** 나란히 놓는 것은 「이 둘에 공통 시계가 있다」는
주장인데 두 실행에는 그런 것이 없다 — 짧은 쪽이 `tpad`의 정지 화면으로 긴
쪽을 기다렸고, 창을 어떻게 잡아도 길이는 실행마다 달라진다.

| 봐야 할 것 | 틀리면 |
|---|---|
| **좌우의 남은 셋이 같은 사람** | 결정성이 깨졌다. 이 프레임의 주장 자체가 거짓이 된다 |
| **첫 조각이 셋만 남은 도식으로 시작**하는가 | 아홉 명이면 `reload`가 마크 뒤로 갔다 |
| ICM 확인 대화의 **네 줄과 합계**를 읽을 수 있는가 | **지금 3초라 짧다**(§8) |
| 폰 여섯이 **끝에 전부 값을 갖는가** | 하나라도 「진행 중」이면 `/me` 갱신 전에 `끝` 마크가 찍혔다 |
| 폰 셋이 **한꺼번에** 값을 받는가 | 차례로 받으면 「먼저 받은 사람이 있다」로 읽힌다 |
| **1위는 딜이 손해, 2·3위는 이득** | 한쪽으로 쏠리면 아무도 안 할 딜이다. 칩 4:3:2가 무너진 것 |
| 둘째 조각 끝에 **종료 덮개**가 뜨는가 | T85 회귀 |

#### `20-abort-refunds-all` · `abort` · 콘솔 단독

환불이 사람마다가 아니라 **무리로** 접힌다. 상점 몫이 0이 되는 유일한 문이다.

| 봐야 할 것 | 틀리면 |
|---|---|
| 확인 대화의 여섯 줄 | §3-2의 값 |
| 「중단에는 상점 몫을 따로 떼지 않습니다」 | 이 문의 성질 자체다 |
| 닫힌 뒤 상단 **상점 몫 0** | 0이 아니면 중단이 rake를 뗀 것. T82 회귀 |

전광판을 뺀 이유는 대회가 닫히면 「대기 중」 검은 화면으로 돌아가 절반이
죽어서다.

### 4-3. 넷 다 공통

- 자홍색 한 장이라도 보이면 슬레이트가 창에 샌 것이다
- 커서가 **글자 위에** 멈춰 있으면 안 된다
- 자막이 **잘리지 않았는가** — `drawtext`는 넘친 글자를 그냥 안 그린다.
  자르는 쪽에 길이 가드가 있지만(`fits`) 폰트 폭이 다르면 빗나갈 수 있다
- 넷 다 **2MB 이하**여야 한다

### 4-4. 정지를 잴 때 조심할 것

**측정기를 그대로 믿지 않는다.** `freezedetect`의 기본 문턱(`-60dB`)은 커서
움직임이나 카운트다운 숫자 하나를 정지로 세어, 실측에서 최장 31.7초를
보고했다. `-70dB`로 재면 8.6초가 되고, 남은 8.6초도 프레임을 보니 **7초가
종료 덮개의 카운트다운**이었다(376초 「6초 뒤」 → 379초 「3초 뒤」).

그래서 절차가 둘이다.

1. `-70dB`로 재서 4초 넘는 구간만 추린다
2. 그 구간의 **시작·끝 프레임 차이 이미지**를 만들어 진짜 정지인지 가린다

```bash
ffmpeg -i a.png -i b.png -filter_complex \
  "[0:v][1:v]blend=all_mode=difference,format=gray,eq=contrast=12:brightness=0.1" \
  -frames:v 1 diff.png
```

**전부 검으면 진짜 정지다.**

정지가 늘 결함인 것도 아니다.

- **의미 있는 정지** — 먼저 끝난 테이블이 서 있는 것은 「병렬」의 증거다
- **참조** — 폰이 번호나 금액을 들고 있는 것은 그 타일의 역할이다
- **낭비** — 조작이 끝났는데 창이 마크까지 열려 있는 것. `20`이 그랬고
  창을 `{ at: '끝', plus: -8 }`로 당겨 0초가 됐다

## 5. 검수가 잡은 것들 — 같은 자리를 다시 밟지 않기 위해

전부 「타입 체크가 통과하고 촬영이 끝났는데 **그림이 거짓말을 하던**」 것들이다.

| 무엇 | 왜 생겼나 |
|---|---|
| 실행마다 남는 셋이 달랐다 | 첫 버튼이 무작위라 승자 스택이 300 흔들렸다. 첫 판 인원을 테이블마다 벌려 5000 차이를 만들었다 |
| **아무도 동의하지 않을 딜** | 큰 스택이 다 먹으면 숏스택이 4,900칩으로 34,200원을 받는다. 딜을 안 하면 3위 상금이 243,000원이다 |
| 커서가 누른 것을 덮었다 | 「ICM 마무리」가 「ICM ●무리」로, 참가 OTP가 `7 2 8 ● 1 2`로 |
| 스틸에 대상이 없었다 | `toBeVisible()`은 스크롤 밖도 통과한다 |
| 폰이 OTP를 안 보여줬다 | `reload()`가 `OtpReveal`의 상태를 지운다 |
| 슬레이트가 결과물에 남았다 | 늦게 연 면은 앞을 검게 채운 **뒤에 영상 0초**를 붙이는데, 거기가 자홍색이다 |
| 판마다 15초를 태웠다 | `declineRebuys`가 좌석이 **빈** 소켓에만 보냈다. 조건이 반대였다 |
| 좌열이 12.2초를 정지로 버텼다 | 길이 차를 촬영 쪽 `linger`로 메우려 했다. **고칠 자리는 배치였다** — 좌우를 앞뒤로 |
| 콘솔이 낡은 값을 그렸다 | 폴링이 없고 조작 성공 때만 `router.refresh()`가 돈다. 탭 전환은 클라 state라 서버를 안 읽는다 |
| **딜러가 지명하는 손이 안 보였다** | 층이 하나인 판은 자리를 한 번 누르고 끝이라 모달이 2초를 못 버텼다. 지명 뒤 읽을 시간을 준다 |
| **넷 중 하나만 멈춰 있었다** | rebuyer의 테이블만 맨 뒤로 돌렸다. 그 판단이 「차례로 돈다」를 전제했는데, 동시에 돌면 리바인 창을 오히려 덜 쓴다 |
| **두 사람이 차례로 옮겼다** | 주석은 「나란히」인데 코드는 단계 순서만 나란히 두고 각 단계 안이 `await` 순차였다 |
| **폰 셋이 차례로 값을 받았다** | `bringToFront`가 순차를 만들었다. 폰마다 2초씩 세던 것도 6초 정지였다 |
| **자막이 조용히 잘렸다** | `drawtext`는 넘친 글자를 안 그리고 아무 말도 안 한다. 47자가 「…엔트리만」에서 끊겼다 |
| **자막 크기가 프레임마다 달랐다** | 원본 해상도에 그린 뒤 서로 다른 비율로 줄어 17px과 25px로 갈렸다 |
| **폰이 콘솔보다 먼저 움직였다** | 창이 열리자마자 `revealOtp` 둘이 5초를 썼다. 「상점이 풀어서 사람이 본다」가 뒤집혔다 |

## 6. 돌릴 때 걸리는 것

- **촬영 중에 아무 파일도 고치지 마라.** 프로덕션 `next start`인데도 죽는다
  (`code=3221226505`). 원인은 아직 못 잡았다
- **셋을 한 명령으로 잇지 마라.** 하나씩 돌려도 두 번째에서 죽을 때가 있고,
  그때는 다시 돌리면 통과한다. 메모리는 아니다(여유 18GB에서 났다)
- **프론트 빌드가 폰트에서 죽는 일이 잦다.** `Module not found:
  '@vercel/turbopack-next/internal/font/google/font'` — gstatic이 한글 subset
  일부를 끊어서다. 성공한 것이 `.next/cache`에 쌓이므로 **다시 돌리면
  통과한다**(실측 3~4회차)
- **통합 테스트 컨테이너를 재사용하면 DB가 오염된다.** `KEEP_TEST_CONTAINERS=1`로
  여러 번 돌리다 46건이 FK 위반으로 깨졌다. 컨테이너를 내리고 다시 띄우면
  낫는다. `test:int:down`이 네트워크에서 멈추면(개발 컨테이너가 같은 네트워크를
  쓴다) `docker compose -f docker-compose.test.yml up -d`로 직접 띄운다
- **시드는 개발 DB를 지운다.** 촬영마다 다시 깐다
- `ffmpeg-static`의 바이너리가 없으면 `node node_modules/ffmpeg-static/install.js`

## 8. 남은 것

### 8-1. 이 브랜치에서 고칠 것

- **`05`의 ICM 확인 대화가 3초라 짧다.** 14.5초 → 7초 → 3초로 줄이는 동안
  지나쳤다. 네 줄과 합계를 읽을 시간이 필요하다 — 그 표가 이 조각의 핵심이다.
  **다시 짜야 하는 자리**라 지금 판에서는 손대지 않았다
- **커서가 모달 글자를 덮는다.** 승자 결정 모달에서 「4번 · A4」 위에 커서가
  멈춘다. §5에 같은 결함이 이미 있고 스틸은 `shoot()`이 커서를 숨겨 해결했는데,
  움짤은 `revealOtp`처럼 **비켜 놓는** 수밖에 없다

### 8-2. 이 브랜치 밖 — `tickets-audit.md`로

촬영이 잡았지만 제품 쪽이고, 고치려면 도메인 판단과 백엔드·프론트·테스트가
같이 붙는다.

- **중단된 대회의 참가자가 폰에서 「진행 중」에 남는다.** `/me`가 참가를 가르는
  기준이 `FINISHED · ELIMINATED · AWARDED` 셋인데 `CANCELLED`가 빠져 있다.
  환불을 받고도 참가 OTP를 계속 들고 있다
- **콘솔이 「취소」인데 배지는 「등록 열림」**이고, 남은 인원·엔트리·프라이즈풀은
  `–`인데 평균 스택만 값이 남는다

### 8-3. 안 하기로 한 것 — `backlog.md`로

**대회가 닫힌 직후의 새로고침 경로.** 단말이 그 순간 다시 뜨면 T85의 이벤트를
못 받고, SSR이 스냅샷을 못 찾아 「테이블 정보를 불러오지 못했습니다」가 뜬다.

**닫지 않는다.** 딜러 태블릿에는 키보드도 주소창도 없어 사람이 새로고침할 길이
없다 — 그 화면이 나오는 경로는 기기가 스스로 다시 뜨는 경우(크래시 · 절전 복귀 ·
배터리)뿐이고 드물다. 소켓이 살아 있는 정상 경로는 T85의 덮개가 이미 덮는다.

남는 것은 문구 하나다. 그 문장이 「화면을 **새로고침**하거나 운영자에게
알려주세요」라고 **고치라고 시키는데** 대회가 정상적으로 끝난 것이라 고장으로
읽힌다. 대가는 「할 일이 끝난 태블릿 한 대가 직원 손을 부른다」라 급하지 않다.

**결함 대장이 아니라 `backlog.md`에 근거로 남긴다** — 깨진 것이 아니라 드문
경로의 문구가 무뚝뚝한 것이고, 나중에 같은 구멍을 다시 발견했을 때 왜 안
닫았는지가 거기 있어야 한다.
