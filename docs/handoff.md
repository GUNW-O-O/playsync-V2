## 2. 지금 해야 할 것

### 2-1. 촬영 셋

```bash
node scripts/demo-settlement.mjs --only=complete --no-build
node scripts/demo-settlement.mjs --only=chop --no-build
node scripts/demo-settlement.mjs --only=abort --no-build
```

**하나씩 돌린다.** 셋을 한 명령으로 이으면 두세 번째에서 `next start`가
`code=3221226505`로 죽는 일이 반복됐다(§5).

`--no-build`인 이유는 프론트 빌드를 따로 하기 때문이다(§5의 폰트 항목).
`.next`가 없으면 `npm run build -w frontend`를 먼저, 실패하면 다시.

**레벨 1을 10분에서 5분으로 줄인 뒤 아직 한 번도 안 돌렸다.** 이 촬영이
그 값을 확정한다 — 리바인이 마감 전에 일어나는지가 유일한 조건이다.

### 2-2. 자르기

```bash
npm run assets:settlement
```

셋이 다 있어야 돈다. `--settlement`은 인자를 안 받는다 — 하나만 골라 자를
수 있게 두면 반만 있는 그림이 조용히 나온다.

## 3. 무엇을 보고 판정하나

**눈으로 훑지 않는다.** 0.15초짜리는 프레임 샘플에 안 걸리고, 실제로 그렇게
놓쳤다. 아래 셋은 계산으로 재고, 그 다음에 그림을 본다.

### 3-1. 자동으로 재는 것

| 무엇 | 어떻게 | 통과 기준 |
|---|---|---|
| **결정성** | 촬영 로그의 `[판]` 줄을 세 실행 비교 | 판별 승자와 남은 셋이 전부 같다 |
| **슬레이트 누출** | `timeline.json`의 `slateAtMs`가 각 장면의 마크 창 안인지 | 0건 |
| **자홍색** | 합성 프레임의 `VMAX ≥ 240` | 0건. `20-abort`의 222~223은 빨간 「중단」 버튼이다 |
| **대기** | 로그의 `리바인 응답 시간초과` 건수 | **0건.** 한 건이 15초다 |
| **흐름** | 마크 사이 간격 | 아래 표 |

마크 간격 기준값(병렬화 후 실측, `complete`):

```
첫 판 → 병합        51초      (처음 112초였다)
병합 → 둘째 판      57초
둘째 판 → 파이널    31초      (처음 63초였다)
파이널 → 마감 대기   3초
```

파이널 도달이 **+3분 29초**다. 레벨 1이 5분이므로 마감 대기가 90초 안팎이어야
한다. 그보다 훨씬 길면 앞이 느려진 것이고, 리바인이 마감을 넘겼는지부터 본다.

### 3-2. 움짤 넷 — 무엇을 주장하고 어디가 깨지면 무슨 뜻인가

#### `11-entry-not-player` · `complete` · 딜러 T1·T2·T3 + 전광판

세 테이블에서 한꺼번에 올인해 스물이 사라지고, 이어서 T3의 한 자리가 0에서
5,000으로 되살아나며 **엔트리만** 36이 된다.

| 봐야 할 것 | 틀리면 |
|---|---|
| 전광판 남은 인원 35 → 15 | 배경 테이블이 소켓으로 안 돌았다 — 필드가 준 게 가짜다 |
| 엔트리 35 → 36인데 **사람 수는 그대로** | 둘이 같이 움직이면 분모가 사람 수라는 뜻. `itm-scaling` 회귀 |
| 상금 목록 다섯 줄 → 여섯 줄 | 리바인이 경계(36)를 못 넘겼다. 35명으로 시작하는 이유가 무너진다 |
| T3에서 0인 자리가 5,000으로 부활 | 원인이 화면에 없다. 전광판(결과)만 남아 인과가 안 읽힌다 |
| 세 테이블이 **동시에** 줄어드는가 | 차례로 줄면 병렬이 풀린 것이다 |

#### `03-four-tables-to-one` · `complete` · 좌석 둘 + 콘솔 + 폰 둘

상점이 좌석을 풀고, 사람이 폰에서 참가 OTP를 다시 보고, 그 번호를 새 자리
태블릿에 넣는다. **둘이 같은 박자로 움직인다.**

| 봐야 할 것 | 틀리면 |
|---|---|
| 폰에 **OTP 여덟 자리가 떠 있는가** | 「참가 OTP 조회」 버튼만 있으면 `revealOtp` 실패. 이 프레임의 주장이 사라진다 |
| 병합 전후 번호가 **같은가** | 다르면 재발급된 것 — 「같은 번호로 다시 앉는다」가 거짓 |
| 옮겨 앉은 뒤 **스택이 그대로** | 줄면 칩이 좌석에 묶인 것. T29 회귀 |
| 콘솔 남은 인원 16 · 엔트리 36 | 병합이 사람을 잃었거나 콘솔이 낡은 값을 그린다 |
| 좌석 해제가 **두 단계**로 | 탭 → 자리 토글 → 「고른 자리 해제」가 화면의 설계다 |
| 커서가 OTP 숫자를 안 가리는가 | 여덟 자리 중 하나가 덮이면 번호를 대조할 수 없다 |
| **해제 둘이 먼저, 착석 둘이 나중**인가 | 한 사람씩 끝나면 같은 조작의 반복이지 「합쳐지는 중」이 아니다 |

#### `05-two-doors-same-ledger` · **좌열 `chop` · 우열 `complete`**

넷 중 유일하게 실행을 가로지른다. 왼쪽은 콘솔에서 합의한 숫자를 적고,
오른쪽은 펠트에서 끝까지 쳐서 정한다.

| 봐야 할 것 | 틀리면 |
|---|---|
| **좌우의 남은 셋이 같은 사람** | 결정성이 깨졌다. 첫 버튼 무작위가 승자를 뒤집었다는 뜻이고, 이 프레임의 주장 자체가 거짓이 된다 |
| 폰 여섯이 **끝에 전부 값을 갖는가** | 하나라도 「진행 중」이면 `/me` 갱신 전에 `끝` 마크가 찍혔다 |
| **1위는 딜이 손해, 2·3위는 이득** | 한쪽으로 쏠리면 아무도 안 할 딜이다. 칩 4:3:2가 무너진 것 |
| 확인 대화 「합계」가 걷은 돈과 같은가 | 찹 계산이 등식을 깼다 |
| 좌우가 **같은 순간**인가 | 한쪽만 이미 닫혀 있으면 창이 잘못 잡혔다 |
| 한쪽이 오래 정지하지 않는가 | 두 실행 길이가 어긋난 것이다. 짧은 쪽은 `tpad`이 마지막 프레임을 복제한다 |

기준값 — chop `544,464 / 412,452 / 274,284`,
complete `615,600 / 372,600 / 243,000`.

#### `20-abort-refunds-all` · `abort` · 콘솔 단독

환불이 사람마다가 아니라 **무리로** 접힌다. 상점 몫이 0이 되는 유일한 문이다.

| 봐야 할 것 | 틀리면 |
|---|---|
| 확인 대화의 여섯 줄 | 진행 중 3명 150,000 · 탈락 28명 725,000 · 상금 받은 4명 0 · 이미 나간 상금 388,800 · 상점 나가고 남은 돈 536,200 · **걷은 돈 1,800,000** |
| 「중단에는 상점 몫을 따로 떼지 않습니다」 | 이 문의 성질 자체다 |
| 닫힌 뒤 상단 **상점 몫 0** | 0이 아니면 중단이 rake를 뗀 것. T82 회귀 |

전광판을 뺀 이유는 대회가 닫히면 「대기 중」 검은 화면으로 돌아가 21초 중
15초가 죽어서다.

### 3-3. 넷 다 공통

- 자홍색 한 장이라도 보이면 슬레이트가 창에 샌 것이다
- 커서가 마지막에 **글자 위에** 멈춰 있으면 안 된다
- 타일 하나가 오래 정지해 있으면 창이 넓거나 `tpad`이 길게 붙은 것이다
- 넷 다 **2MB 이하**여야 한다

## 4. 검수가 잡은 것들 — 같은 자리를 다시 밟지 않기 위해

전부 「타입 체크가 통과하고 촬영이 끝났는데 **그림이 거짓말을 하던**」 것들이다.

| 무엇 | 왜 생겼나 |
|---|---|
| 실행마다 남는 셋이 달랐다 | 첫 버튼이 무작위라 승자 스택이 300 흔들리고, 둘째 판에서 첫 판 승자 둘이 그 300으로 다퉜다. 첫 판 인원을 테이블마다 벌려 5000 차이를 만들었다 |
| **아무도 동의하지 않을 딜** | 큰 스택이 다 먹으면 `85,000 : 4,900 : 4,700`이 되고, 칩 비율로 나누면 숏스택이 4,900칩으로 34,200원을 받는다. 딜을 안 하면 3위 상금이 243,000원이다 |
| 커서가 누른 것을 덮었다 | 「ICM 마무리」가 「ICM ●무리」로, 참가 OTP가 `7 2 8 ● 1 2`로 |
| 스틸에 대상이 없었다 | `toBeVisible()`은 스크롤 밖도 통과한다 |
| 폰이 OTP를 안 보여줬다 | `reload()`가 `OtpReveal`의 상태를 지운다 |
| 슬레이트가 결과물에 남았다 | 늦게 연 면은 앞을 검게 채운 **뒤에 영상 0초**를 붙이는데, 거기가 자홍색이다 |
| 판마다 15초를 태웠다 | `declineRebuys`가 좌석이 **빈** 소켓에만 보냈다. 묻는 대상은 「스택 0인데 아직 좌석에 있는 사람」이라 조건이 반대였다 |
| 테이블을 차례로 돌렸다 | 설계와 마크는 「동시에」인데 순차였다 |

## 5. 돌릴 때 걸리는 것

- **촬영 중에 아무 파일도 고치지 마라.** 프로덕션 `next start`인데도 죽는다
  (`code=3221226505`). 스크립트나 `package.json`도 마찬가지다 — 한 판을
  그렇게 날렸다
- **셋을 한 명령으로 잇지 마라.** 두세 번째에서 같은 코드로 죽는다. 원인은
  아직 못 잡았다. 메모리는 아니다(32GB · 여유 16GB에서 났다).
  `reuseExistingServer: true`라 앞 실행이 정리되는 창과 다음 기동이 겹치는
  것이 유력하지만 확정 못 했다
- **프론트 빌드가 폰트에서 죽는 일이 있다.** `Module not found:
  '@vercel/turbopack-next/internal/font/google/font'` — gstatic이 한글 subset
  100여 개 중 몇 개를 끊어서다. 성공한 것이 `.next/cache`에 쌓이므로 **다시
  돌리면 통과한다**(실측 3회차)
- **시드는 개발 DB를 지운다.** 촬영마다 다시 깐다
- `ffmpeg-static`의 바이너리가 없으면
  `node node_modules/ffmpeg-static/install.js`

## 7. 이 브랜치에서 안 고치는 것

촬영이 잡았지만 제품 쪽이고, 고치려면 도메인 판단과 백엔드·프론트·테스트가
같이 붙는다. `tickets-audit.md`에 결함으로 남긴다.

- **중단된 대회의 참가자가 폰에서 「진행 중」에 남는다.** `/me`가 참가를 가르는
  기준이 `FINISHED · ELIMINATED · AWARDED` 셋인데 `CANCELLED`가 빠져 있다.
  환불을 받고도 참가 OTP를 계속 들고 있다 — 그 파일 주석이 경계하던 구멍에
  중단이 그대로 들어간다
- **콘솔이 「취소」인데 배지는 「등록 열림」**이고, 남은 인원·엔트리·프라이즈풀은
  `–`인데 평균 스택만 값이 남는다
