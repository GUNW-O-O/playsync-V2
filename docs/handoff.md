### 1-1. 코드는 다 됐다

태스크 일곱이 끝났고, 그 위에 검수가 잡은 결함 여덟이 들어갔다.

| 무엇 | 어디 |

| 계획 — 태스크 일곱 | [`superpowers/plans/2026-08-24-settlement-demo-frames.md`](./superpowers/plans/2026-08-24-settlement-demo-frames.md) |

**설계 문서가 코드보다 낡았다.** 검수에서 셋이 바뀌었고 아직 문서에 안 갔다 —
파이널 인원 여섯 → **아홉**, 프레임 ③의 타일 `880×550`·`293×634` →
**`882×550`·`294×634`**(짝수여야 한다), abort 프레임이 콘솔·전광판 둘 →
**콘솔 단독**. SSOT 커밋에서 맞춘다(§7).

### 1-2. 한 번 완주해서 판정했다 (2026-08-25)

**셋 다 끝까지 돌았다.** 처음 있는 일이다 — 그 전의 실측값은 전부 중단된
실행에서 읽은 것이었다. 판정에서 §4의 자동 검사는 전부 통과했고, **그림이
거짓말을 하는 자리 둘**이 나왔다.

- 프레임 ③의 **좌열이 마지막 12.2초를 정지 화면으로** 버텼다
- 프레임 ②의 **첫 19초 동안 콘솔이 낡은 값**(35 · 35 · 1,575,000)을 그렸다

### 1-3. 그 둘을 고쳤다 (`02fe6eb`)

**자르는 쪽** — 창을 구간 목록으로 바꾸고 실행마다 따로 열 수 있게 했다
(`make-demo-assets.mjs`).

| 무엇 | 하는 일 |
|---|---|
| `windows` | 창을 구간 **목록**으로. 가운데의 죽은 구간을 도려낸다 |
| `windowsByTake` | 실행마다 다른 목록. 짧은 쪽 창을 한 마크 앞에서 연다 |
| `{ at, plus }` | 마크가 없는 자리도 초로 집는다 |

**도려내기는 그 실행의 모든 타일에서 같은 구간이어야 한다.** 한 타일만 잘라
내면 그 타일의 시계가 옆 타일보다 앞서 가고, 프레임 하나가 서로 다른 순간을
보여주게 된다. 그래서 목록이 타일이 아니라 **실행**에 붙는다. 실행이 다르면
(프레임 ③의 좌우) 시계가 애초에 따로라 각자 잘라도 되고, 맞춰야 하는 것은
**합계 길이** 하나뿐이다.

프레임 ③의 좌열을 `마무리 — 셋이 한 화면에 있다`부터 열어 정지를 **12.2초 →
3.3초**로 줄였다. **0으로는 안 맞춘다** — `끝`에서 48.220초를 역산하면 좌열
시작이 414.594초인데 `phone-final-3`의 슬레이트가 414.719초다. 0.13초 차라
프레임 하나만 어긋나도 자홍색이 샌다.

**촬영 쪽** — 콘솔을 마크 **앞**에서 다시 읽는다(`settlement.spec.ts`).

콘솔에는 폴링이 없다. SSR로 한 번 그리고, 조작이 성공할 때 `router.refresh()`로만
다시 그린다(`ConsoleClient`의 `run`). **탭을 옮기는 것은 `setActiveTableId`라는
클라 state라 서버를 다시 읽지 않는다** — 탭 왕복으로는 안 고쳐진다.

잘라 내는 것으로도 안 된다. 그 19초 동안 폰 둘이 참가 OTP를 열고 있고 그것이
프레임 ②의 핵심이다. **낡은 것은 시간이 아니라 콘솔 한 장이다.** 그래서
`병합` 마크와 `마무리 — 셋이 한 화면에 있다` 마크 앞에 `console_.reload()`를
넣었다.

### 1-4. 그래서 지금

- 자르는 쪽 변경은 **지금 촬영본으로 확인했다** — 프레임 ③이 1.65 → 1.86MB로
  늘었다. 좌열이 정지 대신 그림을 그린다는 뜻이고 2MB 예산 안이다
- `reload` 두 곳은 **촬영 코드라 재촬영이라야 확인된다**
- `img/`는 커밋 안 했다. 워킹 트리의 파일은 고치기 전 촬영본으로 자른 것이라
  재촬영이 덮는다

## 2. 지금 할 것 — 재촬영 셋

```bash
cd backend && docker compose up -d      # 내려가 있으면
node scripts/demo-settlement.mjs --only=complete --no-build
node scripts/demo-settlement.mjs --only=chop --no-build
node scripts/demo-settlement.mjs --only=abort --no-build
```

**하나씩 돌린다.** 셋을 한 명령으로 이으면 두세 번째에서 `next start`가
`code=3221226505`로 죽는 일이 반복됐다(§6).

**파이프를 걸지 마라.** `| tail`로 받으면 진행 로그가 버퍼에 묶여 끝나야
한꺼번에 나온다. `[판]` 줄을 실시간으로 봐야 결정성을 바로 안다.

`--no-build`인 이유는 프론트 빌드를 따로 하기 때문이다(§6의 폰트 항목).
`.next`가 없으면 `npm run build -w frontend`를 먼저, 실패하면 다시. 프론트
소스가 안 바뀌었으면 있는 `.next`를 그대로 쓴다.

### 자르기

```bash
npm run assets:settlement
```

셋이 다 있어야 돈다. `--settlement`은 **인자를 안 받는다** — 하나만 골라 자를
수 있게 두면 반만 있는 그림이 조용히 나온다.

## 3. 앞 완주의 실측값

**재촬영이 이 값을 갱신한다.** `reload` 둘이 들어가 마크가 2초쯤 밀린다.

### 3-1. 시간

| | complete | chop | abort |
|---|---|---|---|
| 촬영 한 번 | 9.6분 | 8.2분 | 7.6분 |
| 첫 판 → 병합 | 75.6초 | 72.2초 | 65.9초 |
| 병합 → 둘째 판 | 82.8초 | 78.8초 | 72.6초 |
| 둘째 판 → 파이널 | 42.1초 | 42.4초 | 39.8초 |
| 파이널 → 마감 대기 | 6.7초 | 6.1초 | 6.2초 |
| 파이널 도달 | +5분 21초 | +5분 9초 | +4분 31초 |

셋 합쳐 **25.5분.** `CLAUDE.md`의 기준선(12~13분)과 이 문서의 옛 기준값
(51 / 57 / 31 / 3초)은 **둘 다 낡았다** — 옛 기준값은 중단된 실행에서 읽은
것이다. 셋이 서로 일관되므로 차이는 머신 속도다.

**조건은 지켜졌다.** 마감 전이어야 하는 것은 리바인뿐인데(레벨 1이 5분),
리바인이 +2분 1초 · 마감이 +5분 58초로 2.9배 여유였다. 마감 대기는 30.5초로
줄었다.

### 3-2. 숫자

- 남은 셋 — **B4 · C3 · D4** (세 실행 전부 같다). 최후 승자 C3
- 칩 — complete `C3 80,400 / B4 59,300 / D4 40,300`,
  chop `C3 80,000 / B4 59,700 / D4 40,300`
- chop 상금 — `547,200 / 408,348 / 275,652`, 합계 **1,231,200**
- complete 상금표 — `615,600 / 372,600 / 243,000`
- abort 여섯 줄 — 진행 중 3명 150,000 · 탈락 28명 725,000 · 상금 받은 4명 0 ·
  이미 나간 상금 388,800 · 상점 536,200 · 걷은 돈 **1,800,000**

**chop 금액은 실행마다 흔들린다.** 첫 버튼이 무작위라 칩이 수백 움직이고
비율로 나누는 값이라 금액이 따라간다. 고정값으로 단언하지 말고 **딜이
성립하는가**로 본다 — 1위는 딜이 손해, 2·3위는 이득(§4-2).

## 4. 무엇을 보고 판정하나

**눈으로 훑지 않는다.** 0.15초짜리는 프레임 샘플에 안 걸리고, 실제로 그렇게
놓쳤다. 아래는 계산으로 재고, 그 다음에 그림을 본다.

### 4-1. 자동으로 재는 것

| 무엇 | 어떻게 | 통과 기준 |
|---|---|---|
| **결정성** | 촬영 로그의 `[판]` 줄을 세 실행 비교 | 판별 승자와 남은 셋이 전부 같다 |
| **대기** | 로그의 `리바인 응답 시간초과` 건수 | **0건.** 한 건이 15초다 |
| **슬레이트 누출** | 각 면의 `slateAtMs`가 그 면이 쓰이는 창의 **시작보다 앞**인지 | 0건 |
| **자홍색** | 창 구간의 `VMAX ≥ 240` | 0건. `20-abort`의 224는 빨간 「중단」 버튼이다 |
| **크기** | 움짤 넷 | 2MB 이하 |

자홍색은 원본 webm을 창만큼 잘라 재면 된다. 최종 webp는 ffmpeg가 못 읽는다
(§6).

```bash
ffmpeg -ss <창시작-면오프셋> -t <창길이> -i <면>.webm \
  -vf 'signalstats,metadata=print:key=lavfi.signalstats.VMAX:file=-' -f null -
```

### 4-2. 움짤 넷 — 무엇을 주장하고 어디가 깨지면 무슨 뜻인가

#### `11-entry-not-player` · `complete` · 딜러 T1·T2·T3 + 전광판

세 테이블에서 한꺼번에 올인해 스물이 사라지고, 이어서 T3의 한 자리가 0에서
5,000으로 되살아나며 **엔트리만** 36이 된다.

| 봐야 할 것 | 틀리면 |
|---|---|
| 전광판 남은 인원 35 → 15 | 배경 테이블이 소켓으로 안 돌았다 — 필드가 준 게 가짜다 |
| 엔트리 35 → 36인데 **참가 인원은 35 그대로** | 둘이 같이 움직이면 분모가 사람 수라는 뜻. `itm-scaling` 회귀 |
| 상금 목록 다섯 줄 → 여섯 줄 | 리바인이 경계(36)를 못 넘겼다. 35명으로 시작하는 이유가 무너진다 |
| T3에서 0인 자리가 5,000으로 부활 | 원인이 화면에 없다. 전광판(결과)만 남아 인과가 안 읽힌다 |
| 세 테이블이 **한 창 안에서** 줄어드는가 | 같은 순간에 서로 다른 단계면 병렬이다. 하나가 끝나야 다음이 시작하면 풀린 것 |

#### `03-four-tables-to-one` · `complete` · 좌석 둘 + 콘솔 + 폰 둘

상점이 좌석을 풀고, 사람이 폰에서 참가 OTP를 다시 보고, 그 번호를 새 자리
태블릿에 넣는다. **둘이 같은 박자로 움직인다.**

| 봐야 할 것 | 틀리면 |
|---|---|
| **콘솔이 창 처음부터 16 · 36 · 1,620,000** | `reload`가 마크 뒤로 갔다. 이번에 고친 자리다 |
| 폰에 **OTP 여덟 자리가 떠 있는가** | 「참가 OTP 조회」 버튼만 있으면 `revealOtp` 실패. 이 프레임의 주장이 사라진다 |
| 병합 전후 번호가 **같은가** | 다르면 재발급된 것 — 「같은 번호로 다시 앉는다」가 거짓 |
| 옮겨 앉은 뒤 **스택이 그대로** | 줄면 칩이 좌석에 묶인 것. T29 회귀 |
| 좌석 해제가 **두 단계**로 | 탭 → 자리 토글 → 「고른 자리 해제」가 화면의 설계다 |
| 커서가 OTP 숫자를 안 가리는가 | 여덟 자리 중 하나가 덮이면 번호를 대조할 수 없다 |
| **해제 둘이 먼저, 착석 둘이 나중**인가 | 한 사람씩 끝나면 같은 조작의 반복이지 「합쳐지는 중」이 아니다 |

#### `05-two-doors-same-ledger` · **좌열 `chop` · 우열 `complete`**

넷 중 유일하게 실행을 가로지른다. 왼쪽은 콘솔에서 합의한 숫자를 적고,
오른쪽은 펠트에서 끝까지 쳐서 정한다.

| 봐야 할 것 | 틀리면 |
|---|---|
| **좌우의 남은 셋이 같은 사람** | 결정성이 깨졌다. 첫 버튼 무작위가 승자를 뒤집었다는 뜻이고, 이 프레임의 주장 자체가 거짓이 된다 |
| **좌열이 셋만 남은 도식으로 시작**하는가 | 아홉 명이면 `reload`가 마크 뒤로 갔다 |
| 폰 여섯이 **끝에 전부 값을 갖는가** | 하나라도 「진행 중」이면 `/me` 갱신 전에 `끝` 마크가 찍혔다 |
| **1위는 딜이 손해, 2·3위는 이득** | 한쪽으로 쏠리면 아무도 안 할 딜이다. 칩 4:3:2가 무너진 것 |
| 확인 대화 「합계」가 남은 상금과 같은가 | 찹 계산이 등식을 깼다 |
| 좌열의 끝 정지가 **3~4초인가** | 훨씬 길면 두 실행 길이가 다시 벌어진 것이다. `windowsByTake`를 다시 잰다 |

#### `20-abort-refunds-all` · `abort` · 콘솔 단독

환불이 사람마다가 아니라 **무리로** 접힌다. 상점 몫이 0이 되는 유일한 문이다.

| 봐야 할 것 | 틀리면 |
|---|---|
| 확인 대화의 여섯 줄 | §3-2의 값 |
| 「중단에는 상점 몫을 따로 떼지 않습니다」 | 이 문의 성질 자체다 |
| 닫힌 뒤 상단 **상점 몫 0** | 0이 아니면 중단이 rake를 뗀 것. T82 회귀 |

전광판을 뺀 이유는 대회가 닫히면 「대기 중」 검은 화면으로 돌아가 21초 중
15초가 죽어서다.

### 4-3. 넷 다 공통

- 자홍색 한 장이라도 보이면 슬레이트가 창에 샌 것이다
- 커서가 마지막에 **글자 위에** 멈춰 있으면 안 된다
- 타일 하나가 오래 정지해 있으면 창이 넓거나 `tpad`이 길게 붙은 것이다
- 넷 다 **2MB 이하**여야 한다

## 5. 검수가 잡은 것들 — 같은 자리를 다시 밟지 않기 위해

전부 「타입 체크가 통과하고 촬영이 끝났는데 **그림이 거짓말을 하던**」 것들이다.

| 무엇 | 왜 생겼나 |
|---|---|
| 실행마다 남는 셋이 달랐다 | 첫 버튼이 무작위라 승자 스택이 300 흔들리고, 둘째 판에서 첫 판 승자 둘이 그 300으로 다퉜다. 첫 판 인원을 테이블마다 벌려 5000 차이를 만들었다 |
| **아무도 동의하지 않을 딜** | 큰 스택이 다 먹으면 `85,000 : 4,900 : 4,700`이 되고, 칩 비율로 나누면 숏스택이 4,900칩으로 34,200원을 받는다. 딜을 안 하면 3위 상금이 243,000원이다 |
| 커서가 누른 것을 덮었다 | 「ICM 마무리」가 「ICM ●무리」로, 참가 OTP가 `7 2 8 ● 1 2`로 |
| 스틸에 대상이 없었다 | `toBeVisible()`은 스크롤 밖도 통과한다 |
| 폰이 OTP를 안 보여줬다 | `reload()`가 `OtpReveal`의 상태를 지운다 |
| 슬레이트가 결과물에 남았다 | 늦게 연 면은 앞을 검게 채운 **뒤에 영상 0초**를 붙이는데, 거기가 자홍색이다 |
| 판마다 15초를 태웠다 | `declineRebuys`가 좌석이 **빈** 소켓에만 보냈다. 묻는 대상은 「스택 0인데 아직 좌석에 있는 사람」이라 조건이 반대였다 |
| 테이블을 차례로 돌렸다 | 설계와 마크는 「동시에」인데 순차였다 |
| **좌열이 12.2초를 정지로 버텼다** | 길이 차를 촬영 쪽 `linger`로 메우려 했다. 실행마다 달라지는 값이라 앞 커밋이 타이밍을 바꾸자 다시 벌어졌다 — 고칠 자리는 자르는 쪽이었다 |
| **콘솔이 낡은 값을 그렸다** | 폴링이 없고 조작 성공 때만 `router.refresh()`가 돈다. 탭 전환은 클라 state라 서버를 안 읽는다 |

## 6. 돌릴 때 걸리는 것

- **촬영 중에 아무 파일도 고치지 마라.** 프로덕션 `next start`인데도 죽는다
  (`code=3221226505`). 스크립트나 `package.json`도 마찬가지다 — 한 판을
  그렇게 날렸다
- **셋을 한 명령으로 잇지 마라.** 두세 번째에서 같은 코드로 죽는다. 원인은
  아직 못 잡았다. 메모리는 아니다(32GB · 여유 16GB에서 났다).
  `reuseExistingServer: true`라 앞 실행이 정리되는 창과 다음 기동이 겹치는
  것이 유력하지만 확정 못 했다
- **프론트 빌드가 폰트에서 죽는 일이 있다.** `Module not found:
  '@vercel/turbopack-next/internal/font/google/font'` — gstatic이 한글 subset
  100여 개 중 몇 개를 끊어서다. 성공한 것이 `.next/cache`에 쌓이므로 **다시
  돌리면 통과한다**(실측 3회차)
- **시드는 개발 DB를 지운다.** 촬영마다 다시 깐다
- `ffmpeg-static`의 바이너리가 없으면
  `node node_modules/ffmpeg-static/install.js`

### 7-1. 순서

## 8. 이 브랜치에서 안 고치는 것

촬영이 잡았지만 제품 쪽이고, 고치려면 도메인 판단과 백엔드·프론트·테스트가
같이 붙는다. `tickets-audit.md`에 결함으로 남긴다. **둘 다 이번 완주에서
그대로 재현됐다.**

- **중단된 대회의 참가자가 폰에서 「진행 중」에 남는다.** `/me`가 참가를 가르는
  기준이 `FINISHED · ELIMINATED · AWARDED` 셋인데 `CANCELLED`가 빠져 있다.
  환불을 받고도 참가 OTP를 계속 들고 있다 — 그 파일 주석이 경계하던 구멍에
  중단이 그대로 들어간다
- **콘솔이 「취소」인데 배지는 「등록 열림」**이고, 남은 인원·엔트리·프라이즈풀은
  `–`인데 평균 스택만 값이 남는다

**콘솔에 폴링이 없는 것은 결함으로 안 적는다.** 조작 성공 때 다시 읽는 것이
이 화면의 설계이고, 촬영이 그 사실에 맞추면 된다(§1-3). 새로고침 버튼을 다는
것은 도메인 판단이라 이 브랜치 밖이다.
