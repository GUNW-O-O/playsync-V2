## 잔여 목록

열린 것과 감수하기로 한 것이다. 감수는 **모르는 것이 아니라 고치지 않기로 한 것**이다.

| 자리 | 무엇 | 상태 |
|---|---|---|
| 조용한 끊김 | 망이 RST 없이 끊기면 감지가 TCP 타임아웃만큼 늦다. 그동안은 T97 이전과 같다. Redis 하트비트 공백 판정이 필요하다 | 대기 |
| Redis 데이터 유실 | 볼륨 없음 · AOF 손상 뒤의 런타임 재구성이 없다. `pauseTable`은 스냅샷 없는 테이블에 경고만 남기고, 재구성(`rebuildTable`)은 부팅 전용이다 | 대기 |
| 리바인 되돌리기의 이중 장애 | DB가 리바인을 거절한 직후, 칩을 되돌리는 순간 Redis까지 끊기면 칩이 돈 없이 남는다(T100). `error` 로그뿐이다 | 감수 |
| 딜러가 끝내 재개하지 않는 리바인 | 장애로 끊긴 리바인은 딜러의 「이어서 진행」을 기다리므로, 안 누르면 그 테이블의 정산이 멈춘다. 정지 배너가 서 있어 딜러가 안다 | 감수 (T100) |
| 닫힌 대회의 고아 키 | T103이 미뤄 둔 정리(`outage.whenUp()`)가 돌기 전에 프로세스가 재시작되면 Redis 키가 남는다. 부팅 복구는 `LIVE_TOURNAMENT_STATUSES`만 봐서 닫힌 대회를 안 치운다. `Table` 행이 이미 없어 게이트웨이 접속은 거절되므로 기능 영향은 없고 메모리만 남는다 | 감수 (T103) |
| 알림 뒤에 시작하는 리바인 고리 | `handleTournamentClosed`는 `rebuyInFlight`인 테이블만 `closedTables`에 적는다(누수를 막으려 좁혔다). 장애 중 닫은 **뒤** 오프라인 큐가 풀리며 `resolveWinners`가 그제서야 리바인을 시작하면 표시가 없어, 미뤄 둔 정리가 돌기 전까지 유령 프롬프트 창이 열릴 수 있다. 돈은 `NOT_CLOSED_TOURNAMENT_FILTER`가 막는다(T103 최종 리뷰 I3) | 감수 (드묾) |
| 장애 중 찹 | `chopSession`은 `chopBlocker`가 `isRegistrationOpenLive`로 Redis를 먼저 읽어, 닫는 문 중 유일하게 장애 중 503이다. 돈이 움직이기 전이라 안전하다 | 감수 (T103) |
| 리바인 칩 쓰기와 DB 사이의 프로세스 크래시 | T100이 스냅샷을 먼저 쓰므로, 그 사이에 프로세스가 죽으면 칩은 들어가고 돈은 안 빠진다(상점 손해 방향). 이전 순서에서는 반대로 참가자가 돈을 잃었다 | 감수 (T100) |
| `test:outage`의 빨간불 여유 | 사후 확인(스윕의 `freezeTournament`를 건너뛴다)의 폴드가 복귀 약 16초 뒤에 나서 40초 관찰 창 안의 여유가 약 2.4배다. BullMQ 지연이 늘면 빨간불이 조용히 초록이 된다(초록 쪽은 영향 없음) | 감수 |
| `WsGateway.sweepSockets`의 틱 비용 | 10초마다 모든 소켓에 `ping()`과 `keepalive`를 동기로 보낸다. 12,000명이면 틱마다 쓰기 약 2.4만 번이라 `my_action_server_ms`에 10초 주기 스파이크로 보일 수 있다. 다음 램프에서 본다 | 대기 (측정) |
