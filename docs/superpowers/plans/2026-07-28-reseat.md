# 좌석 재배치(T27) 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 상점이 쉬는 시간에 대회 전체 좌석 배치를 한 번에 다시 짜는 API를 만든다.

**Architecture:** `POST /store/sessions/:id/reseat`가 앉아 있는 전원의 배치 계획을 받는다. 대회의 **모든** 테이블 락을 `tableId` 정렬 순으로 중첩 획득하고, 락 안에서 스냅샷을 다시 읽어 `GamePhase.WAITING`과 참가자 집합을 재확인한 뒤, 바뀐 사람만 DB·스냅샷·좌석 비트맵에 반영한다. 실패하면 아무것도 바뀌지 않는다.

**Tech Stack:** NestJS, Prisma(드라이버 어댑터), Redis(ioredis), class-validator, jest.

## Global Constraints

- 설계 문서는 [`docs/superpowers/specs/2026-07-28-reseat-design.md`](../specs/2026-07-28-reseat-design.md)다. 이 계획과 어긋나면 스펙이 정본이다.
- **버그 수정과 새 검사는 실패하는 테스트를 먼저 만들어 확인한다.** 새 테스트가 처음부터 통과하면 의심한다 — 제품 코드를 일부러 되돌려 빨간불을 본 뒤 복원한다.
- 소유권 검사(`assertTournamentOwnership`)는 **서비스 메서드의 첫 문장**이다. 컨트롤러에만 두지 않는다. 통합 테스트가 서비스를 직접 부르므로, 컨트롤러에만 있으면 우회된다.
- 좌석 범위는 0~8이다(9인 테이블). DTO에도 넣고 **서비스에도 넣는다** — 테스트가 서비스를 직접 부른다.
- 커밋 메시지·코드 주석·문서는 한국어다. 커밋 타입 접두사(`feat:`, `fix:`, `test:`, `docs:`)는 그대로 쓴다.
- 명령은 리포 루트에서 돈다. 통합 테스트는 `npm run test:int -w backend`, 반복 실행은 `KEEP_TEST_CONTAINERS=1`을 앞에 붙인다.
- 통합 테스트에서 Prisma를 닫을 때는 반드시 `closeTestPrisma()`를 쓴다. `$disconnect()`는 pg Pool을 닫지 않아 jest가 종료되지 않는다.

```ts
/**
 * 좌석을 한 번에 다시 짠다. 쉬는 시간에 상점이 누른다.
 *
 * 3/3/3이면 한 테이블로 합쳐 9가 되고, 4/4/5면 6/7로 나뉜다. 한 명씩
 * 옮기는 것이 아니라 판을 다시 짜는 것이라, 앉아 있는 **전원**을 받는다.
 *
 * 언제 할지도 누구를 어디로 보낼지도 사람이 정한다. 서버는 계획을 검증하고
 * 기록한다 — 승자를 계산하지 않고 딜러에게 입력받는 것과 같은 자리다.
 */
async reseat(
  tournamentId: string,
  assignments: ReseatAssignmentDto[],
  ownerId: string,
): Promise<AppliedMove[]> {
  await this.assertTournamentOwnership(tournamentId, ownerId);

  const tournament = await this.prismaService.tournament.findUnique({
    where: { id: tournamentId },
    omit: { dealerOtpHash: true },
  });
  if (!tournament) throw new NotFoundException('세션을 찾을 수 없습니다.');
  if (tournament.status === TournamentStatus.FINISHED) {
    throw new ConflictException('이미 종료된 대회입니다.');
  }

  this.assertPlanShape(assignments);

  // 등장하는 테이블이 전부 이 대회 소속인지. 남의 대회 테이블로 사람을
  // 보내면 좌석 비트맵과 스냅샷이 대회 경계를 넘는다.
  const namedTableIds = [...new Set(assignments.map(a => a.tableId))];
  const named = await this.prismaService.table.findMany({
    where: { tournamentId, id: { in: namedTableIds } },
    select: { id: true },
  });
  if (named.length !== namedTableIds.length) {
    throw new NotFoundException('이 대회의 테이블이 아닌 것이 있습니다.');
  }

  return [];
}

/**
 * 요청 자체의 정합성. DB도 Redis도 보지 않는다.
 *
 * `seatIndex` 범위는 DTO에도 있지만 여기에도 둔다 — 통합 테스트와 다른
 * 호출부는 서비스를 직접 부르므로, DTO에만 있으면 우회된다.
 */
private assertPlanShape(assignments: ReseatAssignmentDto[]) {
  if (assignments.length === 0) {
    throw new BadRequestException('배치가 비어 있습니다.');
  }
  const seenUsers = new Set<string>();
  const seenSeats = new Set<string>();
  const perTable = new Map<string, number>();

  for (const a of assignments) {
    if (!Number.isInteger(a.seatIndex) || a.seatIndex < 0 || a.seatIndex > 8) {
      throw new BadRequestException(`좌석 번호는 0~8입니다: ${a.seatIndex}`);
    }
    if (seenUsers.has(a.userId)) {
      throw new BadRequestException(`같은 유저가 두 번 들어왔습니다: ${a.userId}`);
    }
    seenUsers.add(a.userId);

    const seatKey = `${a.tableId}:${a.seatIndex}`;
    if (seenSeats.has(seatKey)) {
      throw new BadRequestException(`같은 자리에 두 명이 배치됐습니다: ${seatKey}`);
    }
    seenSeats.add(seatKey);

    const count = (perTable.get(a.tableId) ?? 0) + 1;
    if (count > 9) {
      throw new BadRequestException(`한 테이블에 9명을 넘길 수 없습니다: ${a.tableId}`);
    }
    perTable.set(a.tableId, count);
  }
}
```

```ts
/**
 * 테이블 여러 개를 한꺼번에 잠근다.
 *
 * **정렬 순으로 중첩한다.** 순서 규칙이 없으면 두 요청이 서로의 락을 기다려
 * 데드락이 난다(A가 t1을 잡고 t2를 기다리는데 B가 t2를 잡고 t1을 기다린다).
 *
 * 기본 TTL이 `withTableLock`보다 길다. 재배치는 락 안에서 DB 트랜잭션까지
 * 도는데, 그 사이 락이 만료되면 딜러의 `startPreFlop`이 들어와 이 락이
 * 막아야 할 바로 그 경합이 열린다.
 */
async withTablesLock<T>(
  tableIds: string[],
  fn: () => Promise<T>,
  ttlMs = 15000,
  maxWaitMs = 5000,
): Promise<T> {
  const sorted = [...new Set(tableIds)].sort();
  const run = sorted.reduceRight<() => Promise<T>>(
    (next, tableId) => () => this.withTableLock(tableId, next, ttlMs, maxWaitMs),
    fn,
  );
  return await run();
}
```

```ts
    await h.session.reseat(h.tournamentId, [
      { userId: 'a', tableId: t1, seatIndex: 0 },
      { userId: 'b', tableId: t1, seatIndex: 1 },
      { userId: 'c', tableId: t1, seatIndex: 2 },
      { userId: 'd', tableId: t1, seatIndex: 3 },
    ], h.ownerId);

    await assertInvariants(h, '합친 직후');
  });
});

/**
 * 단계마다 도메인 불변식을 본다. 마지막에 한 번만 보면 "어딘가에서
 * 틀어졌다"까지만 알 수 있어서, 틀어진 **첫 순간**을 잡도록 단계 이름을
 * 실패 메시지에 남긴다.
 */
async function assertInvariants(h: Harness, step: string) {
  const bitmaps = await h.redisService.getTournamentTables(h.tournamentId);
  let totalChips = 0;
  let seatCount = 0;

  for (const tableId of h.tableIds) {
    const state = await h.redisService.getSnapShot(tableId);
    const occupied = state
      ? state.players.flatMap((p, i) => (p ? [i] : []))
      : [];
    const bits = [...(bitmaps[tableId] ?? '')]
      .flatMap((c, i) => (c === '1' ? [i] : []));

    expect(`${step}/${tableId}: 비트맵 ${bits}`).toBe(`${step}/${tableId}: 비트맵 ${occupied}`);

    seatCount += occupied.length;
    for (const p of state?.players ?? []) if (p) totalChips += p.stack;
  }

  expect(`${step}: 인원 ${seatCount}`).toBe(`${step}: 인원 4`);

  const rows = await h.prisma.tablePlayer.findMany({ where: { tournamentId: h.tournamentId } });
  expect(`${step}: DB 행 ${rows.length}`).toBe(`${step}: DB 행 4`);
  const dbChips = rows.reduce((sum, r) => sum + r.currentStack, 0);
  expect(`${step}: 칩 총량 ${dbChips}`).toBe(`${step}: 칩 총량 ${totalChips}`);
}
```

## 자체 점검 결과

스펙과 대조해 확인한 것과, 계획을 쓰며 스펙에서 벗어난 것.

**스펙에서 벗어난 것 하나** — 스펙은 "관련 테이블"을 잠근다고 썼는데, 계획은 **대회의 모든 테이블**을 잠근다. 계획에 등장하지 않는 테이블에 사람이 앉아 있으면 그 사람이 계획에서 빠졌다는 사실을 알 수 없기 때문이다. 참가자 집합 검사가 성립하려면 전부 읽어야 하고, 읽는 것은 잠근 뒤여야 한다. 스펙의 "관련 테이블 전부 `WAITING`"도 그만큼 넓어진다.

**스펙이 다루지 않아 계획이 정한 것 둘**
- 빈 테이블은 스냅샷이 없을 수 있다(`createTable`은 좌석 비트맵만 만든다). 없는 것을 진행 중으로 보지 않고, 사람이 오면 살아 있는 스냅샷에서 블라인드 값을 물려받아 새로 만든다.
- 비트맵 갱신을 내리기/올리기 두 루프로 나눈다. 한 루프면 맞바꾸기에서 방금 켠 비트를 꺼 버린다.
