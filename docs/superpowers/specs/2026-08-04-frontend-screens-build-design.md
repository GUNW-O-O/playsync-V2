# T34 — 와이어프레임을 화면으로

**2026-08-04.** 백로그 B7. [`frontend/wireframes/2026-08-02-screens.html`](../../../frontend/wireframes/2026-08-02-screens.html)이
확정한 면 다섯 · 화면 열하나를 실제로 만든다. B6는 독립 티켓으로 세우지 않기로
했으므로(백로그 "완주 경로"), API가 걸리는 것은 여기서 고친다.

## 왜 한 티켓인가

처음에는 면 단위로 T34·T35로 잘랐다가 되돌렸다. 자르는 근거로 삼았던 것이
세션 한도였는데, 실측이 그 근거를 지우지 못한다.

```
와이어프레임 1274줄 = CSS 354 + 마크업 ~800 (요소 540개)
```

값이 전부 하드코딩이라 배선은 통째로 남지만, **디자인 판단은 이미 끝나 있다.**
색·간격·타이포·정보구조·좌석 도식의 배치가 전부 확정된 상태에서 시작한다.
프론트 작업에서 제일 비싼 부분이 그것이다.

남는 위험은 토큰이 아니라 **리뷰**다. 화면 열하나가 한 diff로 오면 읽히지 않는다.
그래서 티켓·브랜치·PR은 하나로 두고 **커밋을 면 단위로 끊는다**. 리뷰어가 커밋
하나씩 볼 수 있으면 자른 것과 같은 효과를 얻으면서, 면과 면 사이에 공유되는
펠트 렌더·CSS 토큰을 두 번 짜지 않는다.

## 세 세계

와이어프레임이 정한 것을 그대로 옮긴다. 읽는 거리와 조명이 달라서 갈랐다.

| 면 | 시각 체계 | 전송 |
|---|---|---|
| 상점 콘솔 · 참가자 폰 | Carbon (`DESIGN.md`) | REST |
| 좌석 태블릿 · 딜러 태블릿 | Carbon 아님. 16:9 고정, 스크롤 없음 | REST + WS |
| 전광판 | Carbon 아님. 10m 판독 | **REST 폴링만** |

CSS는 와이어프레임의 `<style>` 블록이 원본이다. `.tbl` / `.score` 토큰을
`globals.css`에 CSS 변수로 옮기고 Tailwind 임의값으로 참조한다. 색·간격을
새로 정하지 않는다 — 그 판단은 B5에서 끝났다.

보드는 장수만 그린다. 채운 칸이 깔린 카드, 점선 칸이 아직 안 나온 카드다.
무늬는 서버에 없고 앞으로도 없다(카드는 물리다).

테이블은 회전하지 않는다. 좌석 태블릿은 딜러가 위(건너편), 딜러 태블릿은
딜러가 아래(자기 앞)다. **같은 테이블을 180° 돌린 것이고 좌석 번호는 그대로다.**
고개를 들면 진짜 테이블이 있으므로 화면이 눈과 어긋나는 순간 그게 곧 오조작이다.

## 데이터 흐름

### 전광판은 WS가 아니다

`GET /playsync/dashboard/:tournamentId` 폴링이다. 명세가 그렇게 정한 이유가
코드에 있다 — 조회가 곧 블라인드 시계를 미는 일이다.

```ts
// redis.service.ts:282
async getFullTournamentInfo(id: string) {
  const raw = await this.redis.hgetall(key);
  const blindField = await this.checkAndSyncBlindLevel(id);   // ← 여기서 시계가 민다
```

서버에 별도 타이머를 두지 않는 이유는 상태를 미는 코드가 한 곳뿐이라야 레벨과
마감이 두 갈래로 자라지 않기 때문이다. 그래서 **전광판은 대회 내내 틀어 둔다.**

갈라지는 구간은 휴식이다. 그때는 `startPreFlop`이 거부되므로 미는 것이 폴링뿐이다.
판정은 응답의 `blindField.isBreak`이고, 서버가 `lv === 99`인 레벨을 휴식으로
세운다(`redis.service.ts:420`). 화면이 판단하지 않는다.

**`null` 구간을 "대기 중"으로 그린다.** 시작 전에는 Redis 스냅샷이 없어
`getDashboardInfo`가 `null`을 200으로 내보내고, 없는 대회와 구별되지 않는다
(T33에서 확인한 것). 전광판은 이 구간을 에러가 아니라 시작 전 상태로 다룬다.

### 태블릿 둘은 WS

| | 초기 | 실시간 | 보내는 것 |
|---|---|---|---|
| 좌석 게임 | `GET /playsync/:tableId` | `renderGame` · `REBUY_PROMPT` | `PLAYER_ACTION` · `REBUY_RESPONSE` |
| 딜러 게임 | 같음 | `renderGame` | `DEALER_ACTION` |

핸드셰이크는 `POST /api/ws-ticket`(Next route handler)이 대신 받은 1회용 30초
티켓으로 한다. 액세스 토큰은 브라우저로 내려가지 않는다 — T24가 세운 규칙이고
이 티켓에서도 유지한다.

### 자격 증명

| 화면 | 무엇을 든다 |
|---|---|
| 좌석 대기 | 없음. 참가 OTP가 자격 증명이다 |
| 좌석 게임 | `accessToken` 쿠키 — 실은 **좌석 토큰**(`role: SEAT_ROLE`) |
| 딜러 대기 | 없음. 딜러 OTP |
| 딜러 게임 | `dealerToken` 쿠키 |
| 전광판 | 없음 |
| 콘솔 · 폰 | `accessToken` 쿠키 — 사용자 로그인 토큰 |

`POST /tournaments/:id/enter`의 응답 키가 `accessToken`이고 안에 든 것은
좌석 토큰이다(`entry.service.ts` 끝 — `sub`·`tournamentId`·`tableId`·`seatIndex`·
`role: SEAT_ROLE`). **쿠키 이름을 그대로 재사용한다.** 태블릿은 사용자 로그인을
하지 않으므로 실제 기기에서는 두 값이 한 브라우저에 같이 있을 일이 없다.

감수하는 것: 데모를 한 브라우저에서 돌리면 폰 로그인과 태블릿 입장이 서로를
덮어쓴다. `frontend/e2e` 하네스가 이미 컨텍스트를 나눠 쓰므로 촬영은 영향이 없고,
손으로 확인할 때는 창을 갈라야 한다.

## 백엔드에 더하는 것 하나

**`GET /tournaments/:id/seats` — 공개, 가드 없음.**

좌석 대기 화면은 앉기 **전에** 점유된 자리를 알아야 한다. 와이어프레임은 이걸
`renderSeatList` WS로 적었는데 성립하지 않는다 — 대회 스코프 구독도 티켓을
요구하고(`ws.gateway.ts:105` "신뢰의 출처가 티켓 소비다"), 티켓은 JWT를 보고
발급된다. 아직 OTP를 넣지 않은 태블릿은 **자격 증명이 하나도 없다.**

점유는 Redis 비트맵에만 있다.

```
tournament:{tournamentId}:seat   해시
  field: table:{tableId}   value: "010010000"   (9자리, 1이 점유)
```

내주는 REST 라우트가 없다. `GET /dealer/:tournamentId`는 `Table` 행만 준다.

**공개 REST를 더하고 대기 화면이 폴링한다.** 게이트웨이의 티켓 규칙을 깨지
않는 쪽을 택했다. 경계가 새로 뚫리지도 않는다 — 같은 화면이 부르는
`POST /tournaments/:id/enter`가 이미 가드 없는 공개 라우트이고, 이유도 같다
(OTP 자체가 자격 증명이라 그 앞에 가드를 세울 수 없다). 좌석 점유는 초당
바뀌는 값이 아니라서 폴링으로 충분하고, 전광판이 이미 같은 선례다.

버린 것 — **티켓 없는 대회 스코프 구독을 예외로 허용하는 것.** 실시간이고
마크업도 안 바뀌지만, 게이트웨이가 한 문장으로 서 있는 규칙에 예외를 내는
값이 "좌석 도식이 1초 빠르다"뿐이다. 위협 모델을 다시 써야 한다.

동시 지정의 최종 판정은 그대로 `enter`의 409다. 폴링이 늦어 이미 찬 자리를
누를 수 있고, 그건 **막는 것이 아니라 지는 것**이다(`@@unique([tableId,
seatPosition])`의 P2002).

## 딜러 대기 화면

와이어프레임에 그림이 없는 유일한 화면이다. **좌석 대기 화면의 배치를 복사하고
누르는 대상만 자리에서 테이블로 바꾼다.** 명세가 안 그린 것을 명세가 그린
문법으로 메운다.

`/dealer/[id]`를 `/dealer?store=`로 옮긴다. URL에 대회가 박히면 그게 곧 기기별
설정이라 대회마다 딜러 태블릿을 손으로 고쳐야 한다 — 좌석 태블릿에 자리를
기억시키지 않는 것과 같은 이유다.

읽기는 `GET /tournaments/stores/:storeId`(대회 목록) → `GET /dealer/:tournamentId`
(테이블 목록), 쓰기는 `POST /dealer/auth`다. 인증 성공 시 `authenticateDealer`
서버 액션이 `dealerToken`을 httpOnly 쿠키로 심는 지금 동작을 그대로 쓴다.

## 게임 화면을 둘로 가른다

지금 `GameClient`는 한 화면이 `isDealer`로 갈라진다(3:1 분할, 오른쪽이 조작
패널). 명세는 **180° 돌린 두 화면**이라 한 컴포넌트에 담기지 않는다.

- 공유: 펠트 렌더(좌석 아홉·보드·팟·사이드팟). `seatOrder` 방향만 인자로 받는다
- 좌석 전용: 액션 버튼 + 슬라이더, 리바인 오버레이, 탈락 오버레이
- 딜러 전용: 핸드 시작, 좌석 누르기(내보내기), 승자 결정 오버레이

승자 결정 오버레이에 **"보드 하이" 버튼**을 넣는다. 누르면 폴드하지 않은 전원을
한 그룹으로 채워 `DEALER_ACTION`에 실어 보낸다. 서버에 별도 엔드포인트를 만들지
않는 이유는 돈이 나가는 경로를 하나로 유지하기 위해서다.

## 탈락 오버레이의 트리거

서버가 "너 탈락했다"를 보내지 않는다. 클라이언트가 받는 이벤트는 `renderGame`과
`REBUY_PROMPT` 둘뿐이다.

**프론트가 유추한다.** 리바인을 거절했거나(`REBUY_RESPONSE { accept: false }`)
프롬프트가 오지 않은 채 `renderGame`에서 내 좌석이 사라지면 탈락이다.

백엔드에 이벤트를 더하지 않는 쪽을 택했다. 유추가 틀려도 잃는 것이 화면 전환
타이밍뿐이고(칩·순위·상금은 폰이 들고 있다), 새 이벤트는 게이트웨이에 브로드캐스트
경로를 하나 더 만든다. B6를 B7에 접은 원칙 그대로 — **걸리는 것만 그때 고친다.**

오버레이는 "폰에서 확인하세요" 한 줄과 카운트다운을 띄우고 대기 화면으로
돌아간다. 순위·상금은 사람에게 붙는 정보이고, 그 자리는 다음 사람이 앉을
자리이기 때문이다.

## 지우는 것

- `frontend/src/app/(terminal)/dealer/[id]/` — `/dealer?store=`로 옮긴다.
  `action.ts`(서버 액션)는 살려서 옮긴다
- `PokerTable.tsx` · `ActionPanel.tsx` — 공유 펠트와 두 조작 패널로 재작성
- 목업 핸들러가 가로채는 `/api/auth/login` 경로 — 실존 로그인 코드가
  `${BACKEND_URL}/auth/login`으로 rewrite를 우회하고 있어 규약이 둘이다.
  `apiFetch`는 프로덕션 호출자가 0개다. 화면을 얹으면서 하나로 합친다

**역할 불일치 404의 빈 본문도 여기서 닫는다.** 미들웨어가 상태 코드는 맞게
내지만 백지가 뜬다. `/_not-found`가 생겼으므로 rewrite가 가능해졌고, 상점
콘솔 커밋에 접는다 — 그 면의 가드가 `STORE_ADMIN`이라 실제로 보이는 자리다.

## 테스트

기준선은 프론트 단위 52건이다. 재작성이 파일을 지우므로 **무엇을 살릴지 먼저
정한다.**

| 살리는 것 | 왜 |
|---|---|
| `page.test.tsx`의 토큰 유출 검사 2건 | T24가 심은 것. `accessToken`·`dealerToken` 값이 클라이언트 prop 어디에도 없어야 한다 |
| `GameClient.test.tsx`의 티켓 실패 3건 | 티켓 발급 실패·403·문구 없음이 화면에 배너로 보이는지 |

새로 붙이는 것은 상태 분기다.

| 파일 | 무엇 |
|---|---|
| 전광판 | `isBreak` 전환, `null` → "대기 중" |
| 좌석 대기 | 점유 비트맵이 점선으로, `enter` 409가 문구로 |
| 좌석 게임 | 탈락 트리거(리바인 거절 · 좌석 소멸) |
| 딜러 게임 | 좌석 순서 반전, 보드 하이가 폴드 안 한 전원을 채움 |

**시각은 단언하지 않는다.** 색이나 간격을 테스트에 박으면 화면을 고칠 때마다
빨개진다. `frontend/e2e`가 회귀에 끼지 않는 것과 같은 이유다.

백엔드는 `GET /tournaments/:id/seats` 하나가 늘어난다. 통합 테스트를 하나 붙인다 —
비트맵이 없는 대회(시작 전)와 있는 대회에서 각각 무엇이 나오는지.

## 하지 않는 것

- **통합 어드민 화면.** 플랫폼 운영자용 신규 면이라 도메인 서사에 기여하는 것이
  없다(백로그가 이미 접었다)
- **좌석 보정(딜러 명령).** T27~T29의 해제 + OTP 재입장이 그 일을 한다
- **`/tournaments/[id]/seat`와 좌석 경합 모달.** T28이 좌석 확정을 결제에서
  입장으로 옮기면서 사라졌다
- **`/me`의 포인트 잔고·거래 내역.** 데모가 보여줄 것은 참여와 OTP 흐름이고,
  잔고는 시드가 세운다(T32)
- **`middleware` → `proxy` 개명.** Next 16 경고만 뜨고 빌드는 통과한다.
  미들웨어 테스트와 같이 움직여야 해 별건으로 둔다
