# 프론트엔드 구조 및 기능 명세

작성일: 2026-07-19

## 목적

Playsync를 오프라인 홀덤펍 사업자용 SaaS로 잡는다. 이 문서는 프론트엔드에
어떤 면(surface)이 있고, 각 면에서 사용자가 무엇을 하는지 정의한다.

백엔드는 현재 MVP다. 이 명세가 앞서고 백엔드가 따라온다.

## 테넌트 모델

**상점(Store)이 테넌트 경계다.**

홀덤펍 사업자 하나가 상점 하나를 갖고, 대회·블라인드 구조는 모두 그 상점에
속한다. 플랫폼 운영자는 상점 위에 있으며 전체를 감독한다.

딜러는 계정이 아니라 **역할**이다. 상점 직원이 대회마다 딜러 단말을 열 뿐,
로그인할 사용자 계정을 갖지 않는다.

## 네 개의 면

성격이 다른 네 종류의 화면이 있다. 한 Next.js 앱에 라우트 그룹으로 담는다.
그룹마다 레이아웃이 분리되므로 콘솔의 사이드바와 단말의 전체화면이 자연스럽게
갈린다.

```
app/
  login/  register/            인증
  (player)/                    플레이어 개인 폰
  (console)/                   상점주 + 플랫폼 운영자
  (terminal)/                  딜러 단말, 좌석 태블릿
```

| 면 | 기기 | 사용자 | 성격 |
|---|---|---|---|
| player | 개인 스마트폰 | 플레이어 | 모바일 우선, 하단 탭 |
| console | 데스크톱 | 상점주 / 운영자 | 사이드바 + 테이블 |
| terminal | 좌석 태블릿, 딜러 단말 | 플레이어 / 딜러 | 전체화면, 크롬 없음 |

랜딩 페이지는 만들지 않는다. 진입점은 로그인이다.

전광판은 별도의 면이 아니라 상점주 콘솔의 하위 화면이다 — 상점 기기에서 열어
TV에 띄운다.

## 핵심 사용자 흐름 — 등록에서 착석까지

이 흐름이 이 명세의 중심이다. 개인 폰과 공용 태블릿을 잇는 지점이 제품의
성격을 결정한다.

1. 플레이어가 폰으로 로그인한다.
2. 포인트를 충전한다.
3. 대회를 찾아 들어가서 **앉을 테이블을 고르고** 등록한다. 이때 세 가지가 함께
   일어난다 — 포인트 차감, 참가 확정, 고른 테이블 선점. 하나라도 실패하면 전부
   취소된다. 포인트만 빠지고 자리가 없는 상태는 만들지 않는다.
4. 대회 상세 화면이 참가 완료 상태로 바뀌고, 대회 정보와 함께 선택한 테이블
   번호와 6자리 OTP가 표시된다.
5. 플레이어가 그 테이블로 가서 빈 자리에 앉는다.
6. 그 태블릿에 **테이블 위치를 찍고 OTP를 입력**한다. 좌석은 고르지 않는다.
7. 검증을 통과하면 시스템이 그 테이블의 빈 좌석 하나에 배치하고, 태블릿이 게임
   화면으로 바뀐다.

### 테이블은 유저가 고르고, 좌석은 딜러가 정리한다

**테이블 선택은 유저 몫이다.** 대회를 조회하면 테이블별 남은 자리가 보이고,
원하는 테이블을 골라 등록한다. 실제로 그 자리에 가서 앉는 것도 오프라인의
유저다.

좌석 번호는 고르지 않는다. 태블릿은 자기 위치를 모르므로 진입할 때 테이블만
묻고, 좌석까지 물어봐야 시스템이 검증할 방법이 없다. 시스템은 빈 좌석에 임의로
앉히고, **앉은 자리와 화면 표시가 어긋나면 딜러가 딜러 단말에서 옮긴다**.

딜러는 테이블 앞에 서서 실제 착석 상태를 보고 있는 사람이다. 이 도메인에서
물리 세계와 데이터를 맞추는 최종 권한은 딜러에게 있다. 좌석 정리도 같다.

태블릿에 위치를 심어두지 않는 이유는 기기를 옮기거나 교체할 때마다 재설정해야
하기 때문이다.

### 자리를 옮기게 되는 경우

테이블 밸런싱으로 이동하면 기존 좌석 세션이 해제되고, 폰과 태블릿 양쪽에 이동
안내가 뜬다. 새 테이블에서 **같은 OTP로** 다시 착석한다.

탈락하면 세션이 해제되고 태블릿은 빈 좌석 화면으로 돌아간다.

## OTP는 대회 단위 식별자다

플레이어와 딜러가 같은 메커니즘을 쓴다. 대회에 참가하거나 대회를 맡으면 그
대회에 한정된 6자리 코드를 하나 받고, 단말 앞에서 그 코드로 자신을 식별한다.

| | 플레이어 OTP | 딜러 OTP |
|---|---|---|
| 발급 시점 | 대회 등록 | 대회 생성 |
| 확인하는 곳 | 폰의 대회 상세 | 상점주 콘솔의 대회 상세 |
| 쓰는 곳 | 좌석 태블릿 | 딜러 단말 |

대회 참가 중에는 계속 유효하다. 밸런싱으로 자리를 옮기거나 단말이 꺼졌다
켜져도 같은 코드로 다시 들어온다. 탈락하거나 대회가 끝나면 무효가 된다.

만료 카운트다운이나 재발급 장치는 두지 않는다. 대회 하나에 코드 하나다.

딜러 OTP는 상점주가 콘솔에서 확인해 직원에게 알려준다. 딜러는 계정이 없으므로
로그인하지 않는다.

## 면별 명세

### 인증

| 화면 | 내용 |
|---|---|
| 로그인 | 닉네임 + 비밀번호 |
| 회원가입 | 닉네임 + 비밀번호 |

### (player) — 개인 폰

플레이어가 폰으로 하는 일은 **대회에 들어가기까지**다. 게임 자체는 좌석
태블릿에서 한다.

| 화면 | 내용 |
|---|---|
| 지갑 | 잔여 포인트, 충전, 거래 내역 |
| 대회 찾기 | 상점별 예정·진행 대회. 바이인, 시작 스택, 등록 마감 여부 |
| 대회 상세 | 블라인드 구조, 상금 구조, 테이블별 남은 자리와 테이블 선택, 등록 버튼. 참가 완료 후에는 선택한 테이블과 OTP를 함께 표시 |
| 내 기록 | 참가 이력, 순위, 상금 |

잔액이 부족하면 등록 버튼 대신 충전으로 유도한다.

### (console) — 상점주

`stores/[storeId]/` 아래. 필수 기능만 담는다.

| 화면 | 내용 |
|---|---|
| 대시보드 | 진행 중 대회, 오늘 참가자 수와 매출 |
| 대회 목록 | 상태별 목록, 생성 |
| 대회 상세 | 운영 콘솔 — **딜러 OTP**, 등록 마감, 리바인 처리, 테이블 현황, 강제 종료 |
| 전광판 | 대회 상세에서 여는 TV용 전체화면. 아래 별도 기술 |
| 블라인드 구조 | 목록, 생성, 레벨 배열 편집 |

딜러 계정 관리 화면은 없다. 딜러는 역할이므로 관리할 계정이 없다.

### (console) — 플랫폼 운영자

`admin/` 아래.

| 화면 | 내용 |
|---|---|
| 상점 목록 | 전체 상점과 상태 |
| 상점 상세 | 해당 상점의 대회와 매출 (읽기 전용) |
| 회원 | 검색, 포인트 조정 |

정산·감사 로그는 이번 범위 밖이다.

### (terminal) — 좌석 태블릿

빈 좌석 상태에서는 진입 화면만 보인다 — 테이블 위치 선택과 OTP 입력. 좌석은
묻지 않는다.

착석 후에는 게임 화면이다. 내 스택, 팟, 커뮤니티 상황, 액션 버튼과 베팅
슬라이더. 카드는 실물이므로 화면에 없다.

### (terminal) — 딜러 단말

딜러가 게임 진행의 트리거다.

| 기능 | 설명 |
|---|---|
| 세션 열기 | 딜러 OTP 입력 |
| 핸드 시작 | 프리플랍 개시 |
| 액션 진행 | 스트리트 전환 |
| 승자 입력 | 실물 카드를 보고 승자를 순서대로 입력. 사이드팟 분배는 시스템이 계산 |
| 리바인 | 리바인·애드온 처리 |
| 좌석 정리 | 좌석별 닉네임과 스택을 보고 실제 착석에 맞게 이동 |

### 전광판 — 상점 TV

상점주 콘솔의 대회 상세에서 열어 TV에 띄운다. 한 번 띄우면 그대로 방치되는
화면이므로 콘솔 크롬 없이 전체화면으로 조판하고, 멀리서 읽히도록 크게 키운다.

| 항목 |
|---|
| 대회명 |
| 남은 인원 / 총 인원 |
| 현재 블라인드 레벨, 다음 레벨까지 남은 시간 |
| 휴식 중 여부 |
| 평균 스택 |
| 총 상금 |
| ITM 라인 |

연결이 끊기면 화면에 크게 표시한다. TV는 아무도 지켜보지 않으므로 조용히
멈추면 아무도 알아채지 못한다.

## 접근 제어

미인증 사용자는 로그인으로 보낸다. 권한이 없는 경로는 404로 처리한다 — 403은
상점의 존재 여부를 알려준다.

상점 소유권은 URL의 `storeId`마다 서버에서 확인한다. 프론트의 가드는 UX를 위한
것이고, 실제 권한 판정은 백엔드가 한다.

`(terminal)`은 사용자 로그인이 아니라 OTP로 진입한다.

전광판은 상점주 세션으로 연다. 상점 기기에서 띄우는 화면이므로 별도의 공개
경로를 두지 않는다.

## 이 명세가 새로 요구하는 것

현재 백엔드에 없는 것들이다.

- 좌석 단위가 아닌 **테이블 단위 선점**
- 대회의 테이블별 잔여 좌석 조회 (유저가 고를 수 있게)
- 대회 단위 OTP 발급·검증 (플레이어는 등록 시, 딜러는 대회 생성 시), 좌석 세션
- 딜러 단말에서의 좌석 이동
- 등록 시 포인트 차감·참가 확정·테이블 선점의 원자적 처리
- 포인트 충전
- 전광판 전용 조회
- 플랫폼 운영자용 상점 전체 조회
