# 와이어프레임

[`2026-08-02-screens.html`](./2026-08-02-screens.html) — 브라우저로 연다.
외부 리소스가 없는 한 파일이라 그냥 열면 된다.

**항목**: backlog B5(프론트 기능 명세). 선행 산출물은
[화면 목록](../../docs/superpowers/specs/2026-07-27-frontend-screens-design.md)이고,
이 문서는 그 목록을 그림으로 확정한 것이다. 다음은 B7(구현)이다.

`docs/`가 아니라 여기 있는 이유: 이 문서를 읽는 사람은 `frontend/src`를 짜는
사람이고, 화면 하나를 만들 때마다 옆에 열어 두는 것이다. 판단의 기록은
`docs/`에 남지만 이건 작업대에 두는 도면이다.

## 무엇이 들어 있나

면 다섯 · 화면 열 하나. 화면마다 **읽기 / 쓰기 엔드포인트**를 붙였다 —
그려 놓고 응답 shape을 지어내는 것을 막기 위해서다.

| 면 | 화면 |
|---|---|
| 상점 콘솔 | 대회 상세(좌석 도식 · 좌석 해제 · 딜러 OTP) |
| 전광판 | 평상시 · 휴식 |
| 좌석 태블릿 | 대기(자리 고르기 + OTP) · 게임 · 리바인 · 탈락 |
| 딜러 콘솔 | 딜러 화면 · 승자 결정 |
| 참가자 폰 | 대회 상세 · 내 참가 |

## 이 문서가 정한 것

- **세계를 셋으로 가른다.** 상점 콘솔은 `DESIGN.md`(Carbon) 그대로, 폰은 그
  톤만, **전광판과 태블릿은 Carbon을 쓰지 않는다.** 읽는 거리와 조명이 다르다 —
  Carbon의 weight-300 디스플레이는 모니터 앞 한 사람을 위한 것이라 10m 밖에서
  안 읽힌다.
- **테이블은 회전하지 않는다.** 온라인 홀덤은 보는 사람을 항상 화면 아래에
  놓는데, 여기서는 보는 사람이 둘이라 결과가 갈린다 — 참가자 태블릿은 딜러가
  위(건너편), 딜러 태블릿은 딜러가 아래(자기 앞)다. 같은 테이블을 180°
  돌린 것이고 좌석 번호는 그대로다. 고개를 들면 진짜 테이블이 있으므로,
  화면이 눈과 어긋나는 순간 그게 곧 오조작이다.
- **보드는 장수만 보여준다.** 채워진 칸이 깔린 카드, 점선 칸이 아직 안 나온
  카드다. 이것만으로 페이즈가 읽힌다(플랍 3 · 턴 4 · 리버 5). 무늬는 서버에
  없고 앞으로도 없다.
- **태블릿 둘은 16:9 안에서 끝난다.** 스크롤이 없다 — 밀어야 보이는 정보는
  못 본 정보다. 딜러 화면의 9행 좌석 표를 없애고 펠트의 자리를 직접 누르게
  바꾼 이유이기도 하다.
- **자리는 사람이 고른다.** 기기가 자리를 기억하면 그게 곧 기기별 설정이라
  대회마다 스무 대를 손봐야 한다. 대기 화면이 게임 화면과 같은 배치의 작은
  도식을 보여주고, 앉은 의자 번호를 그대로 누른다. 잘못 앉으면 딜러가
  **내보내기**로 뺀다.
- **탈락은 폰으로 보낸다.** 순위·상금은 사람에게 붙는 정보이고 폰이 이미
  들고 있다. 태블릿은 "폰에서 확인하세요" 한 줄과 카운트다운 뒤 대기 화면으로
  돌아간다 — 다음 사람이 앉을 자리이기 때문이다.
- **전광판은 대회 내내 틀어 둔다.** 조회가 곧 시계를 미는 일이다
  (`getFullTournamentInfo` → `checkAndSyncBlindLevel`). 서버에 별도 타이머를
  두지 않는 이유는 상태를 미는 코드가 한 곳뿐이라야 레벨과 마감이 두 갈래로
  자라지 않기 때문이다. 갈라지는 구간은 **휴식**이다 — 그때는 `startPreFlop`이
  거부되므로 미는 것이 폴링뿐이다.

## 화면 목록 문서에서 삭제되는 항목

- **좌석 보정(딜러 명령).** 만들지 않는다. 상점이 좌석을 해제하고 사람이
  OTP로 다시 앉는 경로(T27~T29)가 이미 그 일을 한다.
- **`/tournaments/[id]/seat`(좌석 선택)와 좌석 경합 모달.** T28이 좌석 확정을
  결제에서 입장으로 옮기면서 사라졌다. `POST /tournaments/payment`의 몸통은
  `{ tournamentId }` 하나다.
- **`/me`의 포인트 잔고·거래 내역.** 데모가 보여줄 것은 대회 참여와 OTP
  흐름이고, 잔고는 시드가 세운다(T32).
