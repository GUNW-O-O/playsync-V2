# 촬영 하네스

README에 넣을 데모 영상을 만드는 자리다. **회귀 테스트가 아니다** — 회귀는
백엔드의 세 계층(단위 · 통합 · 시나리오)이 잡는다. 여기서만 할 수 있는 것은
화면 넷이 같은 대회를 동시에 비추는 장면이고, 그건 브라우저 없이 못 만든다.

```bash
cd backend && docker compose up -d   # 무대를 깐다 (DB를 지우고 다시 만든다)
npm run test:e2e                     # 루트에서. 개발 서버는 떠 있으면 재사용한다
```

영상은 `e2e/recordings/<테스트 제목>/<면>.webm`에 떨어진다. 전부 `.gitignore`다 —
리포에 남길 것은 편집이 끝난 파일뿐이다.

## 무대는 시드가 깐다

`backend/prisma/seed.ts`가 상점 · 대회 · 테이블 둘 · 참가자 여덟을 만들고
**거기서 멈춘다.** 좌석도 앉히지 않고 대회도 시작하지 않는다. 그 둘이 데모가
보여줄 장면 자체이기 때문이다.

시드는 같은 내용을 리포 루트 `.demo-seed.json`에도 쓴다. 촬영 스크립트가 대회를
**이름이 아니라 id로** 가리키기 위해서다 — 이름으로 찾으려면 목록 화면이 먼저
있어야 하고, 그러면 아직 만들지 않은 화면 하나가 모든 장면의 선행 조건이 된다.

```ts
const { tournament, dealerOtp } = manifest;      // 픽스처가 읽어 준다
const table = tableByOrder(manifest, 1);
const otp = playerByNickname(manifest, 'player1').otp;
```

없으면 시끄럽게 죽는다. 무대 없이 진행하면 첫 실패가 404나 로그인 실패로
나타나서, 원인이 "시드를 안 돌렸다"라는 사실이 두세 겹 아래 묻힌다.

## 면이 넷이다

| 면 | 뷰포트 | 무엇 |
|---|---|---|
| `console` | 1440×900 | 상점 콘솔 |
| `scoreboard` | 1920×1080 | 전광판 |
| `tablet` | 1280×720 | 좌석 태블릿 · 딜러 콘솔 (16:9) |
| `phone` | 390×844 | 참가자 폰 |

크기가 곧 설계다. 전광판은 10m 밖에서, 태블릿은 팔 길이에서, 폰은 손 안에서
읽힌다. 하나의 크기로 찍으면 그 차이가 영상에서 사라진다.

```ts
const phone = await stage('phone', 'demo-참가');
const board = await stage('scoreboard', '전광판');
```

`stage`가 면마다 **따로 된 브라우저 컨텍스트**를 연다. 쿠키가 섞이지 않아야
폰의 `demo`와 콘솔의 `owner`가 같은 실행 안에 공존한다. 두 번째 인자가 그대로
영상 파일 이름이 된다.

## 카메라 밖의 손

`fixtures/backstage.ts`에 있는 것은 **화면 없이 일어난다고 선언한 동작**이다.
지금은 로그인(토큰 발급)뿐이다.

경계는 이렇게 긋는다. 상점이 대회를 시작하는 것, 사람이 OTP를 넣고 앉는 것,
딜러가 액션을 받는 것은 장면 자체라 브라우저로 한다. 반면 "player2~7을 미리
앉혀 둔다" 같은 준비는 배경이고, 태블릿 여섯 대를 띄워 여섯 번 찍는 것은
영상에 아무것도 더하지 않으면서 실행 시간만 늘린다.

## 지금 있는 것 / 없는 것

`harness.spec.ts`는 **하네스 자신**을 검사한다. 앱의 화면을 단언하지 않는다 —
화면은 아직 없거나(B7) 다시 그려질 것이고, 그것을 여기서 단언하면 촬영 토대가
화면 한 번 고칠 때마다 빨개진다.

장면 스크립트는 화면이 생기는 순서대로 붙인다. 시드가 깔아 둔 무대가 지원하는
순서는 이렇다.

1. **폰** — `demo`로 로그인, 대회 참가(결제), 참가 OTP 확인
2. **콘솔** — `owner`로 로그인, 대회 시작 (`PENDING` → 진행)
3. **좌석 태블릿** — 참가 OTP 입력, 착석. 테이블 둘에 나눠 앉는다
4. **전광판** — 켜 둔 채로 둔다. 조회가 곧 블라인드 시계를 미는 일이다
5. **딜러 콘솔** — 딜러 OTP로 입장, 프리플랍 시작, 액션, 승자 결정
6. **탈락** — 태블릿은 "폰에서 확인" 모달 뒤 대기 화면으로, 순위는 폰에서
7. **휴식 · 테이블 합치기** — 휴식(lv 99) 동안 콘솔에서 좌석을 해제하고,
   사람이 1번 테이블로 옮겨 다시 OTP를 넣는다. 빈 테이블을 닫는다

블라인드가 레벨당 3분, 휴식이 2분이다. 운영 구조(15~20분)로는 영상 안에서
블라인드가 한 번도 안 오른다. 7번이 휴식 자리에 있는 이유는 `releaseSeats`가
`GamePhase.WAITING`을 요구하는데(T29) 휴식 중에는 `startPreFlop`이 이미
거부하므로 테이블이 자연히 그 상태에 머물기 때문이다.

## webm 말고 다른 것이 필요하면

Playwright가 내놓는 것은 webm 하나뿐이다. README에 붙일 형식으로는 ffmpeg가
바꾼다.

```bash
# 애니메이션 webp (README 임베드용)
ffmpeg -i phone.webm -vf "fps=12,scale=390:-1" -loop 0 -q:v 60 phone.webp

# 면 넷을 한 화면에 (2x2)
ffmpeg -i console.webm -i scoreboard.webm -i tablet.webm -i phone.webm \
  -filter_complex "[0][1]hstack[t];[2][3]hstack[b];[t][b]vstack" demo.webm
```
